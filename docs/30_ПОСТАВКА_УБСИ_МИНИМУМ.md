# Минимальная поставка ПО проверки УБСИ

## Назначение

Поставка предназначена для проверки ЯЛК-96 и ЯТП в составе УБСИ с контролем
фактического питания от АКИП-1160/6. Rigol, E20, БСИ и остальные измеряемые
тракты в операторский маршрут не входят. ЯВП-8 указывается в кратком протоколе
как зачтённая по отдельному производственному контролю, а не как измеренная
стендом.

## Режимы

1. `ЯЛК-96` — контроль питания, 80 рабочих адресов, точки 0 / 3,1 / 6,2 В,
   контактные состояния 0/1 тех же входов, признак обрыва, перегрузка каждого
   физического входа +12/-12 В с контролем
   остальных каналов, адаптер, ИСД и В7-78/1. После сброса В7 подтверждает
   отсутствие остаточного воздействия, затем выход АКИП выключается.
2. `ЯТП` — по умолчанию полный ручной прогон 30 каналов в точках
   0 / 120 / 240 Ом. Быстрый контроль только при 120 Ом оставлен отдельным
   диагностическим режимом и не выдаётся за проверку диапазона по ТУ.
3. `УБСИ по ТУ` — последовательный единый прогон контроля питания, полного
   ЯЛК и трёхточечного ЯТП с одним журналом и итогом `Норма / Не норма` в
   границах перечисленного объёма.

Дополнительная опция `ЯЛК · контактные пороги 1,0 / 2,4 В` запускается отдельно
из карточки ЯЛК. Она проверяет для каждого из 80 адресов состояние `0` при
1,0 В и состояние `1` при 2,4 В. В обязательный совмещённый прогон эта опция
не входит.

## Работа оператора

1. Запустить `OrbitaDesktop.exe`.
2. Выбрать одну из трёх карточек.
3. Нажать `Проверить оборудование`. Состояния адаптера и ИСД отображаются
   всегда; В7 и Р4831 появляются только там, где нужны.
4. Для ЯТП подтвердить подключение Р4831 к общему X123. В одноточечном режиме
   оставить 120 Ом; в полном режиме переставлять 0 / 120 / 240 Ом по запросу.
5. Запустить проверку. Перед каждой точкой ЯТП программа останавливает ход,
   требует установить Р4831 на 0, 120 или 240 Ом и ввести фактическое значение.
   Верхний график показывает свежие отсчёты выбранного канала, нижний —
   отклонение всех каналов на текущей точке. Строка таблицы выбирает канал.
   Этап перегрузки ±12 В включён. По журналу Рокота исправлена группа
   переключателей ИСД: type=3 для источников 95/96 и каналов 1–88.
   Полный живой прогон этого исправления ещё требуется.
6. После завершения доступны два документа: `Краткий отчёт ТУ` с итогами по
   этапам и `Ведомость каналов` с raw, эталонами, погрешностями и графиками.
HTML и CSV автоматически сохраняются в `runs/<идентификатор запуска>/`.

Отдельно приложение создаёт `registrar.db` для изделия, серийных номеров,
замен и этапов КТМА. Подробности измерений остаются в `runs.db`; базу
`parameters.db` каталогизатор не смешивает с ними. В инженерском меню доступен
просмотр состава и рассчитанного итога регистратора.

В совмещённом прогоне сначала выполняется холодное включение АКИП и проверка
готовности УБСИ не более чем за 30 секунд. Затем проверяется фактическое
питание при `24 / 27 / 35 В`, ток не более `0,4 А` при нормативной точке `27 В`
 (на 24/35 В ток фиксируется как наблюдение), выдержка `19 В / 5 минут`
и `37 В / 1 минута`. После выдержек источник возвращается на `27 В`, и только
потом продолжаются ЯЛК и ЯТП. После нормального завершения, Stop или ошибки
выход источника выключается.

Кнопка `Проверить оборудование` выполняет отдельную последовательность:
сначала включает АКИП на `27 В` с пределом `0,6 А`, затем проверяет ИСД,
В7 и локальные источники данных, выдерживает 3 секунды на загрузку питаемого
от АКИП адаптера и только после этого проверяет UDP-поток адаптера. После
успешной проверки оборудования питание остаётся включённым до запуска либо
явной безопасной остановки.

Показание тока АКИП является суммарным током питания УБСИ и используется для
критерия `не более 0,4 А`. Требование ТУ к входному току отдельного
измерительного канала `не более 2 мкА` из этого показания не определяется и в
текущей минимальной поставке автоматически не проверяется.

При отключённых входах ЯЛК обрыв считается нормой, если пересчитанное значение
строго ниже `0 В` и бит `signal=1`. Наблюдаемое на стенде состояние
`raw=0x0400`, `analog=0`, около `−0,97 В` соответствует этому критерию.

Инженерские страницы скрыты из операторского интерфейса. Переключение
оператор/инженер выполняется клавишей `F12`.

Каноническая карта архитектуры и границ доказанности находится в поставке в
`docs/ktma/`.

## Где находятся исполняемые сценарии

- исходники: `data/scenarios/ubsi_yalk_tu_5_6.yaml`,
  `ubsi_ytp_tu_5_6.yaml`, `ubsi_ytp_120_check.yaml`,
  `ubsi_ulk_combined_check.yaml`, `ubsi_yalk_contact_thresholds.yaml`;
- рядом с собранным приложением: `scenarios/*.yaml`;
- в установленной поставке: `<каталог выпуска>/scenarios/*.yaml`.

Приложение загружает сценарии только из каталога `scenarios` рядом именно с
тем `OrbitaDesktop.exe`, который запущен. Сообщение «нет исполняемого сценария»
означает, что запущена неполная/старая копия либо рядом с EXE нет нужного YAML.
