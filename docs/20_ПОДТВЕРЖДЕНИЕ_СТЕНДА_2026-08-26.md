# Подтверждение стенда КТМА — 26.08.2026

Это факты, полученные безопасными проверками: чтением конфигурации Windows,
ICMP, HTTP GET и чтением В7. Команд ИСД, адаптеру RS-485, источникам и
коммутации не отправлялось.

## Подтверждённое

| Узел | Результат |
|---|---|
| ПЭВМ стенда | `DESKTOP-5EO9J5A`, Windows 11 Pro 26100 |
| Удалённый доступ | SSH доступен по Wi-Fi адресу ПЭВМ `192.168.0.31` для пользователя `Azerty` |
| ИСД | `192.168.0.101`, HTTP отвечает форматом Delphi `type=1num=...val=...work=...` |
| В7-78/1 | VISA `USB0::0x164E::0x0DAD::TW00053184::INSTR`; `READ?` вернул три значения около `-0.005 В` |
| NI-VISA | установлен Runtime 5.4 с 64-разрядной поддержкой |
| Возможный адаптер RS-485 | `.115`, ICMP, MAC `00-35-65-03-74-06`; роль пока не доказана |

## Что не подтверждено

- UDP-пакеты адаптера на `1001/1101`; пассивный приём ничего не поймал, а
  активная команда режима до сверки А.1 не допускается.
- маршруты ИСД для нагрузок, аналоговых и контактных каналов УБСИ;
- подключение Р4831: в текущем отчёте присутствует только `COM1`, поэтому
  прежний `COM7` нельзя считать действующим;
- Я2М-66М и МБ26.20. Для УБСИ 5.6 МБ26.20 не требуется.

## Почему SSH работает только по `.31`

У ПЭВМ одновременно назначены `192.168.0.50/24` на Ethernet и
`192.168.0.31/24` на Wi-Fi. Это две разные L2-сети с одинаковой подсетью.
Рабочая станция видит по адресу `.50` устройство с MAC `78-44-76-A1-28-04`,
а не Ethernet ПЭВМ (`00-E0-4B-61-03-6F`). Поэтому для удалённой работы сейчас
используется `.31`. Настройку адресов или маршрутов нельзя менять наугад:
сначала нужно выбрать отдельную подсеть для проводного стенда либо временно
отключить Wi-Fi при его настройке.

## Следующее безопасное действие

По схеме А.1 выбрать один отключённый/контролируемый маршрут ИСД и одну
ячейку. Затем запустить запись UDP `1001` и `1101`, выполнить **ровно одну**
согласованную с прошивкой команду выбора режима, и сохранить ответ и MAC
источника. Это превратит кандидата `.115` и номера слов в подтверждённые
данные профиля.
