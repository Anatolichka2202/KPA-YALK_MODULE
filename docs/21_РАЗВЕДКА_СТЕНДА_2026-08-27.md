# Разведка подключённых УБСИ и БСИ — 27 августа 2026

Проверка проведена с ПЭВМ `DESKTOP-5EO9J5A` по SSH через Wi-Fi
`192.168.0.31`. Команды ИСД, источник питания, генератор и магазин
сопротивлений в режим удалённого управления не переводились.

| Подсистема | Фактический результат |
|---|---|
| ИСД | HTTP на `192.168.0.101` отвечает. |
| В7-78/1 | VISA: `USB0::0x164E::0x0DAD::TW00053184::INSTR`; чтение около `-0,005 В`. |
| VISA | Ровно два ресурса: В7-78/1 и `ASRL1::INSTR` (физический COM1). |
| E20-10 | Не присутствует в PnP как `USB\\VID_0471&PID_2010`; `liborbita` получает `OpenLDevice failed`. |
| Адаптер RS-485 | Ethernet `192.168.0.115`, MAC `00-35-65-03-74-06`; отвечает на ARP. |
| UDP адаптера | Нет кадров и подтверждений на портах `1001/1101` при режимах `0,1,2,6,7,8,11`. |
| Р4831 | COM7 отсутствует; существует только COM1. |
| Rigol и осциллограф | Среди VISA-ресурсов не обнаружены. |
| МБ26.20 | Не виден в PnP как USB/COM-прибор; его роль и интерфейс ПЭВМ пока не подтверждены. |

## Вывод

УБСИ и часть БСИ могут быть запитаны и подключены в измерительную схему, но
на момент проверки у ПЭВМ нет двух потоков, необходимых для автоматического
испытания:

1. E20-10 не передаёт поток «Орбита» в `liborbita`;
2. адаптер RS-485 не передаёт UDP-данные УБСИ.

Поэтому инженерный экран не должен рисовать несуществующие значения и не
может сформировать результат по ячейкам. После появления E20 в Windows и
первого UDP-кадра нужно повторить захват; инструменты
`orbita_telemetry_probe.exe` и `probe_ubsi_adapter_win11.ps1` уже находятся
в выпуске и сохраняют реальные данные без GUI.
