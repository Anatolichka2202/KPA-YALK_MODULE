# ЯВП-8 — рабочий тракт ИСД + В7

Этот документ описывает текущий production backend ЯВП-8. Старые
экспериментальные backends через адаптер КТМА/ROKT сохранены отдельно и не
являются источником измерения для `ubsi.yvp`.

## Физический тракт

```text
Rigol DG-1022Z CH1 → C=1000 пФ → выбранный вход ЯВП-8
выход ЯВП-8 → CH89…CH96 кабеля ЯЛК-96 → ИСД → общая цепь V → В7-78/1
```

ИСД выбирает вход ЯВП, четыре бита коэффициента `KU1…KU4` и выход,
который измеряет В7. АКИП-1160/6 питает УБСИ и не используется как источник
сигнала ЯВП.

## Источники карты

Карта сведена из четырёх проверяемых источников:

1. кабель ЯВП8-2, рисунок Б.6 — цепи входов ЯВП;
2. кабель ЯВП8-1, рисунок Б.5 — цепи `1KU1…8KU4`;
3. `L:\Обмен\Толмачёв Анатолий\ИСД Э3.pdf`, лист 2 — реле и адресные
   перемычки плат A2/A3/A5/A6;
4. исходный код прошивки ИСД `LPC1788/src/easyweb.c`, таблицы `DMTable`,
   `KMTable` и `KMGlobalBusTable` — точная семантика HTTP `type/num`.

Адресные перемычки Э3 дают:

```text
A2 = модуль 7
A3 = модуль 6
A5 = модуль 4
A6 = модуль 3
```

### Выбор входа, HTTP type=2

```text
ЯВП1: 33    ЯВП2: 34    ЯВП3: 35    ЯВП4: 36
ЯВП5: 37    ЯВП6: 38    ЯВП7: 39    ЯВП8: 40
```

Референсный `ЯВП_канал.scn` вычисляет контакт как `channel + 32` и
включает один HTTP-канал `type=2`. Вторая физическая линия кабельной пары
не является второй программно коммутируемой командой выбора входа.

### KU1…KU4, HTTP type=2

```text
ЯВП1:  1, 2, 3, 4     ЯВП2:  5, 6, 7, 8
ЯВП3:  9,10,11,12     ЯВП4: 13,14,15,16
ЯВП5: 17,18,19,20     ЯВП6: 21,22,23,24
ЯВП7: 25,26,27,28     ЯВП8: 29,30,31,32
```

Референсные сценарии КПА задают следующие KU-биты:

```text
0,25: нет битов
0,5:  KU1
1:    KU2
2:    KU3
4:    KU1 + KU3
8:    KU4
32:   KU2 + KU4
```

Файлы-источники находятся в
`03_Референсные_программы\04_КПА\TU_BSU_FTK_06\подсценарии`:
`ЯВП_коэф_1_канал.scn` и `ЯВП_исдК*.scn`.

### Выход ЯВП → В7

Каналы ЯВП 1…8 соответствуют `CH89…CH96`. HTTP `type=1` и `type=3`
принимают номер аналогового канала ИСД; прошивка затем сама переводит его
в модуль DM и реле общей шины через `DMTable` и `KMGlobalBusTable`:

```text
ЯВП1: 89    ЯВП2: 90    ЯВП3: 91    ЯВП4: 92
ЯВП5: 93    ЯВП6: 94    ЯВП7: 95    ЯВП8: 96
```

Перед `type=3` DM-выход того же аналогового канала отключается командой
`type=1`, `value=0`, `work=0`, чтобы ИСД не зажимал внешний сигнал ЯВП.
Именно такую последовательность (`а <канал> выкл`, затем `ш <канал> 1`)
использует референсный `10_ЯЛК_перегрузки.scn`. При снятии маршрута
отключаются `type=3` и DM-выход, затем выполняется полный сброс ИСД.

## Исполняемая методика

`ubsi.yvp` зарегистрирован как backend `yvp.v7_isd`. Для каждой точки:

```text
Rigol OUTPUT OFF → безопасный сброс ИСД
→ выбрать вход контактом `channel + 32`
→ выбрать выход на В7
→ выставить KU-биты текущего физического канала
→ задать частоту и Vpp Rigol
→ OUTPUT ON → выдержка → измерить Vrms В7
→ при частоте >= 10 Гц также измерить частоту
→ сохранить raw и расчётные значения
→ OUTPUT OFF
```

Амплитуды воздействия:

```text
K=0,25 → 8 Vpp; K=0,5 → 4 Vpp; K=1 → 2 Vpp; K>1 → 1 Vpp
```

Частоты: `0,15; 20; 250; 500; 1800; 2000; 4000 Гц`.

В любой ошибке и после завершения выполняются `Rigol OUTPUT OFF`, снятие
маршрутов и `full_reset` ИСД. Консольный `orbita_yvp_v7_probe.exe` запускает
тот же backend с ограничением по каналам, коэффициентам и частотам.

## Открытый commissioning

Карты ИСД подтверждены схемами, референсной программой и таблицами прошивки.
Локальный имитатор моделирует состояние команд `type=2`, аналогового
`type=1`, выхода `type=3`, частоту и амплитуду Rigol. Напряжение В7
формируется только для согласованного маршрута одного канала. Через эту
модель пройдены все `8 × 7 × 7 = 392` точки: восемь входов, семь KU и семь
частот; расхождений заданного и восстановленного коэффициента нет. Отдельный
прогон с намеренно неверным выходным контактом дал `0 В`, то есть имитатор
действительно контролирует карту, а не возвращает постоянное значение.

Для локального прогона запустить `MilTechStationSimulator.exe`, затем
`orbita_yvp_v7_probe.exe` с профилем `stand_ktma_simulator.yaml` и сценарием
`ubsi_production_yvp.yaml`. Вкладка `ЯВП-8 · ИСД + В7` показывает выбранный
вход, KU, CH89…CH96, команду Rigol и расчётное напряжение В7; там же можно
задать ошибку коэффициента или разорвать тракт.

15.09.2026 на стенде выполнены commissioning-прогоны канала 1 при 20 Гц.
Rigol прямым VISA-запросом подтвердил `VPP`, `SIN 20 Гц`, `2 Vpp` и
`OUTP=ON`. Исправленная команда выхода использует аналоговые каналы
`89…96`, а вход — одиночные контакты `33…40`. Проверены все восемь
маршрутов выхода и все семь KU-комбинаций; В7 не обнаружил сигнал 20 Гц.
Для основной точки `вход 33 / CH89 / K=1` измерено `0,001465 В RMS` и
`2,378836 Гц`, то есть только шум. После серии прогонов ИСД перестал
отвечать по HTTP и требует перезапуска. Поэтому физический тракт пока не
подтверждён, backend сохраняет измерения с `INCOMPLETE` и не выдаёт
`НОРМА`.

Также ещё не утверждён приёмочный критерий и не доказана нормативная
амплитудная конвенция расчёта `Rigol Vpp → заряд → В7 Vrms → output Vpp`.
Поэтому acceptance намеренно не применяется.
