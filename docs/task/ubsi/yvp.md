# ЯВП-8 — рабочий тракт ИСД + В7

`ubsi.yvp` использует прямой измерительный backend `yvp.v7_isd`.
Архивный backend адаптера КТМА/ROKT остаётся отдельным диагностическим
вариантом и в этой методике не участвует.

## Физический тракт

```text
АКИП-1160/6, 27 В → питание УБСИ
Rigol DG-1022Z CH1 → C=1000 пФ → выбранный вход ЯВП-8
выход ЯВП-8 → ИСД → общая измерительная шина V → В7-78/1
```

АКИП питает изделие. Источником сигнального воздействия является только
Rigol. ИСД выбирает вход, KU1…KU4 и выход на В7.

## Карты коммутации

Источники карты:

1. кабель ЯВП8-2, рисунок Б.6 — входные цепи;
2. кабель ЯВП8-1, рисунок Б.5 — цепи KU1…KU4;
3. `L:\Обмен\Толмачёв Анатолий\ИСД Э3.pdf`, лист 2;
4. прошивка ИСД `LPC1788/src/easyweb.c`, таблицы `DMTable`, `KMTable` и
   `KMGlobalBusTable`;
5. референсные сценарии КПА `ЯВП_канал.scn`, `ЯВП_коэф_1_канал.scn` и
   `ЯВП_исдК*.scn`.

Вход, HTTP `type=2`:

```text
ЯВП1 33   ЯВП2 34   ЯВП3 35   ЯВП4 36
ЯВП5 37   ЯВП6 38   ЯВП7 39   ЯВП8 40
```

Для выбора входа включается один контакт. Это подтверждается старым
исполнителем `TestYAVP.pas`, который отправляет один запрос
`type=2 num=channel+32`.

Контакты KU1…KU4, HTTP `type=2`:

```text
ЯВП1  1..4    ЯВП2  5..8    ЯВП3  9..12   ЯВП4 13..16
ЯВП5 17..20   ЯВП6 21..24   ЯВП7 25..28   ЯВП8 29..32

K=0,25: нет контактов   K=0,5: KU1   K=1: KU2
K=2: KU3               K=4: KU1+KU3
K=8: KU4               K=32: KU2+KU4
```

Исполняемая карта выхода на В7 находится в
`data/scenarios/ubsi_production_yvp.yaml`:

```text
ЯВП1 44   ЯВП2 29   ЯВП3 30   ЯВП4 31
ЯВП5 71   ЯВП6 72   ЯВП7 88   ЯВП8 73
```

Перед подключением канала к общей шине командой `type=3` аналоговый выход
ИСД того же номера отключается командой `type=1`, чтобы ИСД не зажимал
внешний сигнал.

## Исполняемая последовательность

Для каждого канала и коэффициента:

```text
Rigol OUTPUT OFF
→ включить вход type=2
→ отключить аналоговый выход type=1
→ подключить измерительный маршрут type=3 к В7
→ включить KU-контакты type=2
→ задать SIN, частоту и Vpp Rigol
→ OUTPUT ON
→ выдержать 2 с
→ измерить Vrms В7
→ сохранить уставки, Vrms и расчётный коэффициент
→ OUTPUT OFF
→ снять только включённые процедурой KU, type=3 и вход
```

Глобальный `type=4` reset внутри процедуры не применяется: на живом ИСД он
может заблокировать единственный HTTP worker, если внутренний модуль не
ответил. При Stop, исключении и штатном окончании сначала выполняется
`Rigol OUTPUT OFF`, затем снимаются ровно те маршруты, которые включила
процедура.

Текущие уставки сценария:

```text
K=0,25 → 8 Vpp; K=0,5 → 4 Vpp; K=1 → 2 Vpp; K>1 → 1 Vpp
частоты: 0,15; 20; 250; 500; 1800; 2000; 4000 Гц
```

Это пока commissioning-набор, а не утверждённый acceptance-набор.
Нормативный рабочий диапазон ЯВП — 2…2000 Гц. Референсный сценарий
`ЯВП_8_02_ачх.scn` проверяет 20…2000 Гц и отдельно 4000 Гц как точку
затухания. Частоты 0,15 Гц в нём нет. При выдержке 2 с точка 0,15 Гц не
охватывает даже одного периода: `1 / 0,15 = 6,67 с`.

При K=32 текущая уставка 1 Vpp также непригодна для проверки номинального
усиления: `1000 пФ × 1 В = 1000 пКл`, ожидаемое идеальное значение
`1000 пКл × 32 мВ/пКл = 32 Vpp`. Живой выход ограничивается примерно
`25,2 Vpp`. Референсный сценарий использовал для K=32 уставку 0,16 Vpp.

## Живое подтверждение 17.09.2026

После повторного подключения выполнен одинаковый прогон при `K=4`,
`250 Гц`, `1 Vpp`, питание `26,979 В`, ток `0,137…0,138 А`:

| Канал | В7, Vrms | Наблюдение |
|---:|---:|---|
| 1 | 1,302780 | полезный сигнал, 249,973 Гц |
| 2 | 1,307981 | полезный сигнал, 249,982 Гц |
| 3 | 1,309958 | полезный сигнал, 249,985 Гц |
| 4 | 1,298189 | полезный сигнал, 250,041 Гц |
| 5 | 0,656904 | примерно половина каналов 1…4 |
| 6 | 0,642281 | примерно половина каналов 1…4 |
| 7 | 1,303346 | полезный сигнал; предыдущая серия тех же уставок |
| 8 | 0,027611 | полезного сигнала 250 Гц нет; частотомер видит шум |

Отдельная подача ИСД `3,10 В` на измерительные маршруты показала, что
маршруты 71, 72, 73 и 88 проводят сигнал к В7. Для маршрута 73 измерено
`2,998552 В`, для 88 — `3,043394 В`. Это исключает обрыв участка
`type=3 → общая шина V → В7`, но само по себе не доказывает соответствие
маршрута конкретному физическому выходу ЯВП.

Ослабление каналов 5 и 6 сохраняется при K=0,25 без включённых KU, поэтому
KU-карта не объясняет двукратную разницу. Для канала 8 тот же опыт без KU
также дал только шум.

Доказанный результат локализации:

- Rigol, питание, В7 и общий алгоритм работают на каналах 1…4 и 7;
- измерительная шина В7 работает для используемых маршрутов;
- каналы 5 и 6 устойчиво дают примерно половину уровня;
- канал 8 не даёт полезного сигнала;
- причина остаётся до или внутри ЯВП либо в соответствии физического
  выхода исполняемой карте. Разделить эти варианты текущими измерениями
  нельзя.

Процедура поэтому правильно возвращает `INCOMPLETE`. Выдавать `НОРМА` до
подтверждения карты физических выходов и числового acceptance-критерия
нельзя.
