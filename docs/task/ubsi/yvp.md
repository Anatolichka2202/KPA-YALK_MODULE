# ЯВП-8 — текущий стендовый статус

Этот документ описывает актуальный `master`. Ветка `rebuild/tu-minimal-clean`
используется только как read-only референс подтверждённого тракта УБСИ; код из
неё не переносится автоматически и её acceptance-обходы не являются источником
решения о годности изделия.

Общая карта требований:

[tu-work.md](tu-work.md)

---

# 1. Физический тракт

Для текущей сборки используется:

```text
Rigol DG-1022Z CH1
  ↓
вывод «З» кабеля ЯВП 8-2
  ↓
ЯВП-8
  ↓
коммутация ИСД
  ↓
В7-78/1
  ↓
процедура ubsi.yvp
```

`АКИП-1160/6` питает УБСИ, но не является источником сигнального воздействия
ЯВП.

ROKT-команды ЯВП (`0A 01`, `0A 03`) сохранены в проекте как отдельный
commissioning/diagnostic transport. Текущий production verdict по коэффициенту
усиления и АЧХ формируется не из недекодированного ROKT payload, а из
контролируемого воздействия Rigol и измерения В7.

# 3. Управление Rigol и расчёт коэффициента

Сценарий задаёт амплитуду в `Vpp`. Для коэффициента `K` входная амплитуда по
умолчанию:

```text
Uin_vpp = 2 / K
```

Связующая ёмкость:

```text
C = 1000 пФ
```

Заряд:

```text
Q[pC] = C[pF] * Uin[V]
```

В7 измеряет `Vrms` выходного сигнала. Для синусоиды:

```text
Uout_vpp = Vrms * 2 * sqrt(2)
```

Расчёт:

```text
Kmeas[мВ/пКл] = 1000 * Uout_vpp[V] / Q[pC]
```

Raw-измерение и итоговый критерий сохраняются раздельно. `master` не переносит
из donor политику `manual_confirmed` и не генерирует искусственные значения для
протокола.

# 4. Частотный проход

Текущий production-сценарий использует коэффициенты:

```text
0.25, 0.5, 1, 2, 4, 8, 32 мВ/пКл
```

Все коэффициенты проверяются на опорной частоте:

```text
500 Гц
```

АЧХ снимается на `K = 1 мВ/пКл` по сокращённому набору граничных/контрольных
точек:

```text
2, 6, 20, 500, 1800, 2000, 4000 Гц
```

Критерии текущей реализации:

```text
K:       ±7 % относительно заданного коэффициента
2 Гц:    ±10 % относительно 500 Гц
6 Гц:    ±5 %
20 Гц:   ±5 %
1800 Гц: ±5 %
2000 Гц: ±10 %
4000 Гц: затухание >= 20 дБ относительно 500 Гц
```

Точка 4000 Гц является проверкой затухания выше верхней рабочей частоты, а не
рабочей точкой диапазона 2...2000 Гц.

# 5. В7-78/1: обязательный production timeout

Живой donor-прогон 24.09.2026 воспроизвёл `VI_ERROR_TMO` на первой точке
ЯВП при `MEAS:VOLT:AC?`: три попытки с timeout 5000 мс завершились примерно
через 5,06 с каждая. При неизменной коммутации и timeout 25000 мс та же команда
вернула результат за 7023 мс.

Поэтому профиль `master` фиксирует:

```text
timeout_ms: 25000
voltage_command: MEAS:VOLT:DC?
ac_voltage_command: MEAS:VOLT:AC?
frequency_command: MEAS:FREQ?
```

При timeout во время много-точечного прохода процедура переподключает VISA-сеанс
и повторяет чтение без смены воздействия. Это важно: поздний ответ предыдущего
запроса не должен быть принят за следующую точку.

# 6. Безопасность коммутации

Процедура использует owner-scoped маршруты ИСД.

На переходах и при ошибке:

```text
Rigol OUTPUT OFF
  ↓
release_owner только маршрутов текущего YVP run
```

Глобальный `type=4` reset не является частью production-прохода ЯВП.

Сценарий обязан явно содержать:

```text
mapping_confirmed: true
active_outputs_confirmed: true
```

Без этих флагов активное воздействие не выполняется и шаг не должен выдавать
ложную `НОРМА`.

# 7. Что подтверждено, а что ещё требует живого master-run

Подтверждено donor/live evidence:

```text
CH1 / K=0.25 / 500 Гц
маршрут type=2/33 + type=3/44
Rigol 8 Vpp
MEAS:VOLT:AC?
ответ В7 при timeout 25 с
адресный cleanup после точки
```

В `master` реализованы все восемь строк карты, все коэффициенты, сокращённая
АЧХ, retry/reconnect В7 и owner-scoped cleanup. Unit-регрессия проверяет
алгоритм на fake equipment, но не заменяет живой стенд.

До статуса `COVERED` нужен новый живой прогон актуального `master`, минимум:

```text
8 каналов
все 7 коэффициентов на 500 Гц
АЧХ K=1
точка 4000 Гц
аварийный cleanup / stop
сохранённый structured run и отчёт
```

Отдельная граница покрытия: исходное ТУ УБСИ требует не менее 16
пьезоэлектрических каналов, а текущая физическая процедура называется ЯВП-8 и
обрабатывает 8 каналов. Нельзя считать требование 16 каналов закрытым, пока не
подтверждён второй 8-канальный тракт или другая документированная методика,
которая покрывает оставшиеся каналы.

# 8. Что не возвращать из старых реализаций

Не использовать как production acceptance:

```text
ЯВП -> обычный поток ЯЛК -> адреса 88..96
base + offset для выбора входа или КУ
manual_confirmed, превращающий raw FAIL в OK
синтетические report_measured_value/report_deviation
глобальный type=4 reset для штатного cleanup
```

ROKT ЯВП и `orbita_yvp_rokt_probe` остаются полезными диагностическими
инструментами, но не подменяют независимое измерение В7 в текущем production
тракте.
