# Физическая методика испытания УБСИ

Этот документ отвечает на вопрос:

> Что физически делает стенд и что именно он измеряет?

Требования:

[tu.md](tu.md)

Покрытие:

[tu-work.md](tu-work.md)

Операторское представление:

[operator.md](operator.md)

---

# 1. Общая последовательность

```text
1. проверить готовность оборудования
2. привести стенд в безопасное исходное состояние
3. включить УБСИ
4. проверить питание и готовность
5. выполнить ЯЛК
6. выполнить ЯТП
7. выполнить ЯВП только если commissioning разрешает
8. сохранить structured run
9. сформировать отчёт
10. safe stop
```

Ошибка оборудования не превращается в `НЕ НОРМА` изделия.

---

# 2. Питание

Источник:

```text
АКИП-1160/6
```

Защитный current limit:

```text
0.6 А
```

Он защищает стенд.

Критерий общего тока УБСИ:

```text
<= 0.4 А
```

Это уже оценка изделия.

## Рабочие точки

```text
24 В
27 В
35 В
```

На каждой предусмотренной точке необходимо подтверждать живой тракт УБСИ.

## Пониженное питание

```text
19 В
5 минут
```

Затем:

```text
27 В
повторный ROKT init
свежий ожидаемый кадр
```

## Повышенное питание

```text
37 В
1 минута
```

Затем:

```text
27 В
повторный ROKT init
свежий ожидаемый кадр
```

## OVP

Текущий живой стенд показал, что OVP может ограничить доступное напряжение
примерно 31 В.

Текущая конфигурация использует:

```text
VOLT:LIM 40 В
```

с обратной проверкой.

OVP не отключать.

# 3. Готовность 30 секунд

Последовательность:

```text
питание OFF
  ↓
задать безопасные ограничения
  ↓
27 В
  ↓
питание ON
  ↓
старт секундомера
  ↓
явный запуск ROKT
  ↓
ждать свежий ожидаемый кадр
```

Критерий:

```text
t <= 30 с
```

Старый кадр или старый `alive` до включения не считается доказательством
готовности.

# 4. ЯЛК — физический тракт

```text
ИСД
  ↓
вход ЯЛК УБСИ
  ↓
ЯЛК
  ↓
adapter / ROKT
  ↓
UDP
  ↓
программа

одновременно:

ИСД
  ↓
В7
  ↓
независимый эталон
```

## Почему В7 обязателен

Команда:

```text
"подать 6.20 В"
```

не гарантирует, что на линии физически 6.20 В.

Поэтому для оценки погрешности:

```text
эталон = фактическое измерение В7
```

а не `val`, отправленный ИСД.

---

# 5. ЯЛК — ROKT

Канонический protocol-reference:

[../../reference/protocols/rokt.md](../../reference/protocols/rokt.md)

Кадр ЯЛК:

```text
204 байта
02 00 2B 00
100 x uint16 LE
```

Слово:

```text
analog_code = raw & 0x03FF
contact = (raw & 0x0400) != 0
```

---

# 6. Калибровка ЯЛК

Используются адреса:

```text
97
99
```

Пересчёт:

```text
UяЛК =
    (code - code97)
    * 6.2
    / (code99 - code97)
```

Адрес 98 не использовать как замену 99.

Фактическое напряжение В7 остаётся независимым эталоном для оценки
погрешности.

---

# 7. Основные 80 каналов ЯЛК

Рабочие адреса:

```text
1–28
32–43
45–70
74–87
```

Для каждого канала:

```text
0.0 В
3.1 В
6.2 В
```

На каждой точке:

```text
ИСД задаёт воздействие
  ↓
В7 измеряет фактическое напряжение
  ↓
программа ждёт только свежие кадры ЯЛК
  ↓
берётся серия свежих выборок
  ↓
код переводится в вольты
  ↓
ЯЛК сравнивается с В7
```

---

# 8. Контактные сигналы ЯЛК

Текущая рабочая последовательность использует точки:

```text
0.0 В
0.9 В
2.5 В
```

Ожидаемое цифровое состояние определяется текущей методикой.

UI не должен показывать старые точки `1.0 / 2.4 В`, если сценарий
выполняет `0 / 0.9 / 2.5 В`.

---

# 9. Обрыв ЯЛК

Снять внешнее воздействие.

Дождаться свежего состояния.

Критерий:

```text
U < 0 В
```

Не подменять его проверкой "примерно 0".

---

# 10. Перегрузка ЯЛК ±12 В

Проверяются физические каналы:

```text
1..88
```

Перед началом текущего run должен быть получен baseline.

Для каждого перегружаемого канала:

```text
включить +12 В
  ↓
выдержать подтверждённую паузу
  ↓
получить только свежие кадры
  ↓
сравнить остальные каналы с baseline
  ↓
safe transition

затем аналогично -12 В
```

Для остальных каналов:

```text
delta =
    current_code
    -
    baseline_code
```

Текущий критерий:

```text
abs(delta) <= 2 code
```

Между воздействиями:

```text
снять ±12 В
RESET ИСД
DAC OFF
WAIT
```

Точные baseline-детали и WAIT нельзя додумывать, если они ещё не
подтверждены живым стендом.

После исправления stale UDP необходим новый полный живой прогон актуальной
реализации.

---

# 11. ЯТП — физический тракт

```text
ручной R4831
  +
коммутация ИСД
  ↓
входы ЯТП
  ↓
ЯТП УБСИ
  ↓
adapter / ROKT
  ↓
UDP
```

Р4831 в текущей подтверждённой методике является ручным.

Наличие plugin `signal.resistance` само по себе не разрешает автоматически
управлять физическим Р4831.

---

# 12. ЯТП — ROKT

Запуск:

```text
ROKT 0A 02 00 01 00
```

Кадр:

```text
68 байт
01 00 34 00
32 x uint16 LE
```

Слова:

```text
1..30   измерительные
31      верхняя калибровка
32      нижняя калибровка
```

Специальное значение:

```text
0x8000 = измерения нет
```

---

# 13. ЯТП — точки

Оператор устанавливает Р4831:

```text
0 Ом
120 Ом
240 Ом
```

Каждая точка общая для всех 30 каналов.

Программа должна ждать подтверждения оператора перед продолжением.

---

# 14. ЯВП-8

Каналов: `8`.

Текущий production-тракт не использует адаптер/ROKT для измерения:

```text
АКИП 27 В → питание УБСИ
Rigol CH1 → 1000 пФ → выбранный вход ЯВП
выход ЯВП → ИСД → V → В7
```

Техническая последовательность одной точки:

1. выключить выход Rigol;
2. включить одиночный вход ИСД `type=2`, контакты `33…40`;
3. отключить аналоговый выход ИСД выбранного измерительного канала
   командой `type=1`;
4. подключить этот канал к В7 командой `type=3`;
5. выставить KU1…KU4 выбранного физического канала;
6. задать на Rigol синус, частоту и амплитуду Vpp;
7. включить Rigol, выдержать паузу и измерить В7 в AC Vrms;
8. сохранить исходные уставки и измерение;
9. сначала выключить Rigol, затем снять KU, измерительный маршрут и вход;
10. при Stop/исключении выполнить тот же безопасный порядок.

Глобальный reset ИСД `type=4` процедура не использует, поскольку на живом
стенде он блокировал HTTP worker. Снимаются только маршруты, включённые
самой процедурой.

ROKT-команды `0A 01` и `0A 03` относятся к сохранённому
диагностическому backend и не входят в текущую production-методику.

Карты, нормативные границы, живые результаты 17.09.2026 и открытые
неисправности находятся в [yvp.md](yvp.md). До локализации каналов 5, 6 и
8 и утверждения acceptance-критерия результат ЯВП остаётся `INCOMPLETE`.

# 15. Свежесть данных

Для любого измерения после воздействия:

```text
before_sequence = last_sequence
  ↓
переключить воздействие
  ↓
отбросить накопившееся старое
  ↓
ждать sequence > before_sequence
```

Нельзя привязывать новое воздействие к старому UDP-кадру.

# 16. Safe stop

При:

```text
Stop
timeout
exception
аварии прибора
```

runtime должен попытаться привести все автоматически управляемые активные устройства в безопасное состояние.

Типовой безопасный смысл:

```text
снять активные воздействия ИСД
выключить генератор, если его active commands подтверждены и он был активирован сценарием
отключить питание
остановить transport
```

Если воздействие включено оператором вручную и backend не имеет разрешённой команды его снятия, операторский шаг safe-off должен быть отдельно определён методикой.

Ошибка одного safe-stop действия не должна мешать попытке остановить
остальные устройства.
