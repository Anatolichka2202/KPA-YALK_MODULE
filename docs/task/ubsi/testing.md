# Физическая методика испытания УБСИ

Этот документ отвечает на вопрос:

> Что физически делает стенд и что именно он измеряет?

Требования:

[tu.md](tu.md)

Покрытие:

[tu-work.md](tu-work.md)

Операторское представление:

[operator.md](operator.md)

# 1. Общая последовательность

```text
1. проверить готовность оборудования
2. привести стенд в безопасное исходное состояние
3. включить УБСИ
4. проверить питание и готовность
5. выполнить ЯЛК
6. выполнить ЯТП
7. выполнить ЯВП только если commissioning разрешает
8. сохранить structured run
9. сформировать отчёт
10. safe stop
```

Ошибка оборудования не превращается в `НЕ НОРМА` изделия.

# 2. Питание

Источник:

```text
АКИП-1160/6
```

Защитный current limit:

```text
0.6 А
```

Он защищает стенд.

Критерий общего тока УБСИ:

```text
<= 0.4 А
```

Это уже оценка изделия.

## Рабочие точки

```text
24 В
27 В
35 В
```

На каждой предусмотренной точке необходимо подтверждать живой тракт УБСИ.

## Пониженное питание

```text
19 В
5 минут
```

Затем:

```text
27 В
повторный ROKT init
свежий ожидаемый кадр
```

## Повышенное питание

```text
37 В
1 минута
```

Затем:

```text
27 В
повторный ROKT init
свежий ожидаемый кадр
```

## OVP

Текущий живой стенд показал, что OVP может ограничить доступное напряжение
примерно 31 В.

Текущая конфигурация использует:

```text
VOLT:LIM 40 В
```

с обратной проверкой.

OVP не отключать.

# 3. Готовность 30 секунд

Последовательность:

```text
питание OFF
  ↓
задать безопасные ограничения
  ↓
27 В
  ↓
питание ON
  ↓
старт секундомера
  ↓
явный запуск ROKT
  ↓
ждать свежий ожидаемый кадр
```

Критерий:

```text
t <= 30 с
```

Старый кадр или старый `alive` до включения не считается доказательством
готовности.

# 4. ЯЛК — физический тракт

```text
ИСД
  ↓
вход ЯЛК УБСИ
  ↓
ЯЛК
  ↓
adapter / ROKT
  ↓
UDP
  ↓
программа

одновременно:

ИСД
  ↓
В7
  ↓
независимый эталон
```

## Почему В7 обязателен

Команда:

```text
"подать 6.20 В"
```

не гарантирует, что на линии физически 6.20 В.

Поэтому для оценки погрешности:

```text
эталон = фактическое измерение В7
```

а не `val`, отправленный ИСД.

```text
204 байта

```

```text
analog_code = raw & 0x03FF
contact = (raw & 0x0400) != 0
```

# 6. Калибровка ЯЛК

Используются адреса:

```text
97
99
```

Пересчёт:

```text
UяЛК =
    (code - code97)
    * 6.2
    / (code99 - code97)
```

Адрес 98 не использовать как замену 99.

Фактическое напряжение В7 остаётся независимым эталоном для оценки
погрешности.

# 7. Основные 80 каналов ЯЛК

Рабочие адреса:

```text
1–28
32–43
45–70
74–87
```

Для каждого канала:

```text
0.0 В
3.1 В
6.2 В
```

На каждой точке:

```text
ИСД задаёт воздействие
  ↓
В7 измеряет фактическое напряжение
  ↓
программа ждёт только свежие кадры ЯЛК
  ↓
берётся серия свежих выборок
  ↓
код переводится в вольты
  ↓
ЯЛК сравнивается с В7
```

# 8. Контактные сигналы ЯЛК

Текущая рабочая последовательность использует точки:

```text
0.0 В
0.9 В
2.5 В
```

Ожидаемое цифровое состояние определяется текущей методикой.

UI не должен показывать старые точки `1.0 / 2.4 В`, если сценарий
выполняет `0 / 0.9 / 2.5 В`.

---

# 9. Обрыв ЯЛК

Снять внешнее воздействие.

Дождаться свежего состояния.

Критерий:

```text
U < 0 В
```

Не подменять его проверкой "примерно 0".

---

# 10. Перегрузка ЯЛК ±12 В

Проверяются физические каналы:

```text
1..88
```

На старте процедуры формируется baseline для всех наблюдаемых каналов. Затем
каждое воздействие выполняется отдельно для `+12 В` и `-12 В`.

Для одного воздействия:

```text
восстановить фоновую лестницу ИСД
  ↓
подключить источник +12 В или -12 В
  ↓
снять DAC с перегружаемого канала
  ↓
подключить перегружаемый канал
  ↓
выдержать overload_settle_ms
  ↓
получить только свежие кадры
  ↓
сравнить остальные каналы с baseline
  ↓
release_owner текущей overload-процедуры
```

Для остальных каналов:

```text
delta = current_code - baseline_code
abs(delta) <= 2 code
```

При `88` физических каналах выполняется:

```text
88 × 2 = 176 воздействий
```

Между воздействиями глобальный `type=4` не выполняется. Все включения процедуры
имеют отдельный owner и снимаются через targeted `release_owner`. Если targeted
cleanup не получил подтверждение хотя бы для одного маршрута, это техническая
ошибка стенда, а не результат изделия.

После исправления stale UDP необходим новый полный живой прогон актуального
`master`.

# 11. ЯТП — физический тракт

```text
ручной Р4831
  ↓
входы ЯТП УБСИ
  ↓
adapter / ROKT
  ↓
UDP
```

Рабочая production-процедура ЯТП не использует ИСД. Ранее предполагаемый
`type=7` не является частью подтверждённого тракта.

Старт нового самостоятельного run может включать общую service baseline-команду
ИСД как политику стенда. Это не функциональная зависимость ЯТП.

Р4831 является ручным магазином сопротивлений. Наличие plugin
`signal.resistance` само по себе не разрешает автоматически управлять
физическим Р4831.

# 12. ЯТП — ROKT

Последовательность запуска production:

```text
prepare_ytp_rokt
  ↓
ROKT 0A 02 00 01 00
  ↓
ожидание свежего кадра
```

Кадр:

```text
68 байт
01 00 34 00
32 x uint16 LE
```

Слова:

```text
1..30   измерительные
31      верхняя калибровка
32      нижняя калибровка
```

Специальное значение:

```text
0x8000 = измерения нет
```

# 13. ЯТП — точки

Оператор устанавливает Р4831:

```text
0 Ом
120 Ом
240 Ом
```

Каждая точка общая для всех 30 каналов. Полный маршрут содержит:

```text
30 × 3 = 90 измерительных точек
```

Программа ждёт подтверждения оператора перед продолжением каждой ручной точки.

# 14. ЯВП-8

Каналов:

```text
8
```

## Production-тракт

```text
АКИП-1160/6, 27 В → питание УБСИ
Rigol DG-1022Z CH1 → C=1000 пФ → вход ЯВП-8
выход ЯВП-8 → ИСД → общая шина V → В7-78/1
```

Адаптер КТМА/ROKT в production-измерении ЯВП не участвует.

Для каждого канала используются явные карты входа, KU1..KU4 и измерительного
выхода ИСД. Перед подключением выхода к общей шине В7 аналоговый выход того же
номера выключается, чтобы ИСД не нагружал внешний сигнал.

## Точки и критерии

```text
8 каналов
7 коэффициентов: 0,25 / 0,5 / 1 / 2 / 4 / 8 / 32 мВ/пКл
7 частот: 2 / 6 / 20 / 500 / 1800 / 2000 / 4000 Гц
```

Итого полный живой прогон ЯВП содержит:

```text
8 × 7 × 7 = 392 измерительных точки
```

Опорная частота — `500 Гц`.

Критерии текущего production:

- коэффициент при 500 Гц: `±7 %`;
- АЧХ относительно 500 Гц: `2 Гц ±10 %`, `6/20/1800 Гц ±5 %`,
  `2000 Гц ±10 %`;
- затухание 4000 Гц: не менее `attenuation_min_db` сценария;
- в текущих published сценариях `attenuation_min_db = 20 дБ`.

Амплитуда Rigol задаётся в Vpp:

```text
K:    0,25  0,5  1  2  4   8    32
Vpp:  8     4    2  1  0,5 0,25 0,0625
```

Расчёт:

```text
Q, пКл = C, пФ × Uin, В
Uout,Vpp = Uout,Vrms × 2 × sqrt(2)
Kmeas, мВ/пКл = 1000 × Uout,Vpp / Q
```

## Порядок и безопасность

Перед первым активным воздействием выполняется read-only HTTP probe ИСД. Ошибка
probe завершает шаг техническим `ERROR` до включения Rigol.

Для каждой точки:

```text
Rigol OFF
  ↓
вход ИСД
  ↓
measurement route ИСД
  ↓
KU ИСД
  ↓
Rigol SIN/frequency/Vpp
  ↓
Rigol ON
  ↓
выдержка
  ↓
Vrms В7
  ↓
Rigol OFF
```

Cleanup:

```text
Rigol OFF
  ↓
KU OFF
  ↓
measurement route OFF
  ↓
input route OFF
  ↓
release_owner
```

`type=4` в процедуре ЯВП не используется. Ошибка targeted cleanup является
технической ошибкой стенда.

Актуальная карта ИСД, формулы и результаты контрольных живых измерений:
[yvp.md](yvp.md).

# 15. Свежесть данных

Для любого измерения после воздействия:

```text
before_sequence = last_sequence
  ↓
переключить воздействие
  ↓
отбросить накопившееся старое
  ↓
ждать sequence > before_sequence
```

Нельзя привязывать новое воздействие к старому UDP-кадру.

# 16. Safe stop

При:

```text
Stop
timeout
exception
аварии прибора
```

runtime должен попытаться привести все автоматически управляемые активные устройства в безопасное состояние.

Типовой безопасный смысл:

```text
снять активные воздействия ИСД
выключить генератор, если его active commands подтверждены и он был активирован сценарием
отключить питание
остановить transport
```

Если воздействие включено оператором вручную и backend не имеет разрешённой команды его снятия, операторский шаг safe-off должен быть отдельно определён методикой.

Ошибка одного safe-stop действия не должна мешать попытке остановить
остальные устройства.
