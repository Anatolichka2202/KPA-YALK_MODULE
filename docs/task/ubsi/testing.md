# Физическая методика испытания УБСИ

Документ описывает физические действия актуального `master`: что стенд
коммутирует, чем воздействует, чем измеряет и откуда берётся verdict.

Связанные документы:

- [tu.md](tu.md) — нормативная выжимка;
- [tu-work.md](tu-work.md) — карта покрытия;
- [yvp.md](yvp.md) — детальная методика ЯВП;
- [operator.md](operator.md) — операторский слой.

Ошибка оборудования не превращается в `НЕ НОРМА` изделия. Если состояние
стенда или свежесть данных нельзя доказать, результат шага должен быть
`ERROR`/`INCOMPLETE`, а не браком УБСИ.

---

# 1. Общая последовательность

```text
readiness оборудования
  ↓
адресное безопасное исходное состояние ИСД
  ↓
включение УБСИ
  ↓
питание / готовность
  ↓
ЯЛК
  ↓
ЯТП
  ↓
ЯВП-8
  ↓
structured run / отчёт
  ↓
safe stop
```

Глобальный firmware reset `type=4` не используется как штатный cleanup
измерительных процедур.

---

# 2. Питание

Источник УБСИ:

```text
АКИП-1160/6
```

Защитный current limit:

```text
0,6 А
```

Критерий общего тока изделия:

```text
I <= 0,4 А
```

Рабочие точки:

```text
24 В
27 В
35 В
```

Воздействия выживания:

```text
19 В / 300 с
37 В / 60 с
```

После воздействия напряжения:

```text
вернуть 27 В
  ↓
переинициализировать нужный transport
  ↓
дождаться свежего ожидаемого ответа
```

OVP не отключается. Профиль стенда использует предел 40 В, чтобы не блокировать
точки 35/37 В.

---

# 3. Готовность <= 30 с

Проверка начинается от выключенного питания:

```text
OUTP OFF
  ↓
задать 27 В / безопасный current limit
  ↓
OUTP ON
  ↓
старт таймера
  ↓
инициализация transport
  ↓
свежий ожидаемый кадр
```

Старый кадр, полученный до включения, не является доказательством готовности.

---

# 4. ЯЛК — тракт и эталон

```text
ИСД -> вход ЯЛК УБСИ -> adapter/ROKT -> UDP -> программа
  |
  +-------------------------------> В7-78/1
```

ИСД создаёт воздействие. В7 измеряет фактическое напряжение и является
независимым эталоном; командный `val` ИСД не используется как измеренное
значение.

ROKT-кадр ЯЛК:

```text
204 байта
header 02 00 2B 00
100 x uint16 LE
```

Слово параметра:

```text
analog_code = raw & 0x03FF
contact     = (raw & 0x0400) != 0
```

Калибровочные адреса:

```text
97
99
```

Пересчёт:

```text
U = (code - code97) * 6.2 / (code99 - code97)
```

---

# 5. ЯЛК — 80 рабочих линий

Адреса:

```text
1–28
32–43
45–70
74–87
```

Аналоговый проход:

```text
0 В
3,1 В
6,2 В
```

На каждой точке:

```text
зафиксировать sequence до воздействия
  ↓
скоммутировать ИСД
  ↓
выдержка
  ↓
измерить фактическое U на В7
  ↓
дождаться только свежих кадров ЯЛК
  ↓
усреднить выборку / пересчитать код
  ↓
сравнить ЯЛК с В7
```

Контактный проход production-сценария использует точки:

```text
0 В -> ожидается 0
0,9 В -> ожидается 0
2,5 В -> ожидается 1
```

UI и отчёт должны брать точки из реально исполняемого сценария, а не из
устаревшей подписи.

---

# 6. Обрыв ЯЛК

Внешнее воздействие снимается адресно, затем берётся свежий snapshot.

Критерий требования:

```text
U < 0 В
```

Нулевое или около-нулевое значение не должно подменять критерий обрыва.

---

# 7. Перегрузка ЯЛК ±12 В

Перегружаются только безопасные 80 линий ЯЛК. Следующие физические линии
исключены, поскольку используются ЯВП:

```text
29,30,31,44,71,72,73,88
```

Общие источники:

```text
+12 В -> type=3 / contact 96
-12 В -> type=3 / contact 95
```

Перед первым воздействием один раз формируется фоновое состояние и снимается
baseline. Для каждой полярности и целевой линии:

```text
DAC target OFF
  ↓
dac_off settle
  ↓
общий ±12 В ON
  ↓
type=3 target ON
  ↓
overload settle
  ↓
свежий snapshot
  ↓
сравнить остальные 79 линий с baseline
  ↓
type=3 target OFF
  ↓
общий ±12 В OFF
  ↓
восстановить DAC target
```

Текущий `master`:

```text
overload_settle_ms = 10000
maximum_code_delta = 2
```

Значения из donor с другой выдержкой/дельтой не переносятся автоматически.

Cleanup owner-scoped; глобальный `type=4` не выполняется.

---

# 8. Эталон 6,2 В

Номинал:

```text
6,20 ± 0,03 В
```

Проверка использует В7 и соответствующие калибровочные данные ЯЛК. Значение
только из телеметрии без независимого эталона не считается достаточным для
этой физической проверки.

---

# 9. ЯТП

Физический смысл:

```text
ручной магазин R4831
  ↓
входы ЯТП УБСИ
  ↓
adapter / ROKT
  ↓
UDP
```

Запуск:

```text
ROKT 0A 02 00 01 00
```

Кадр:

```text
68 байт
header 01 00 34 00
32 x uint16 LE
```

Слова:

```text
1..30  измерительные каналы
31     верхняя калибровка
32     нижняя калибровка
```

Специальное значение:

```text
0x8000 = измерения нет
```

Оператор последовательно устанавливает общие точки:

```text
0 Ом
120 Ом
240 Ом
```

На каждой точке проверяются все 30 каналов. Переход к следующему сопротивлению
требует операторского подтверждения.

---

# 10. ЯВП-8 — актуальный production тракт

Старый commissioning через недекодированный YVP ROKT payload больше не является
основным acceptance-трактом.

Текущая физическая цепочка:

```text
Rigol DG-1022Z CH1
  ↓
вывод «З» кабеля ЯВП 8-2
  ↓
C = 1000 пФ / вход ЯВП-8
  ↓
явная коммутация ИСД
  ↓
В7-78/1
  ↓
ubsi.yvp
```

`АКИП-1160/6` в этой части только питает УБСИ.

Входы ЯВП (`type=2`):

```text
33,34,35,36,37,38,39,40
```

Измерительные линии В7 (`type=3`, с analog OFF):

```text
44,29,30,31,71,72,88,73
```

Контакты КУ:

```text
CH1  1..4
CH2  5..8
CH3  9..12
CH4 13..16
CH5 17..20
CH6 21..24
CH7 25..28
CH8 29..32
```

Код коэффициента:

```text
0.25 -> none
0.5  -> KU1
1    -> KU2
2    -> KU3
4    -> KU1+KU3
8    -> KU4
32   -> KU2+KU4
```

Все семь коэффициентов измеряются при 500 Гц. На `K=1` выполняется сокращённая
АЧХ:

```text
2,6,20,500,1800,2000 Гц
```

4000 Гц используется для затухания относительно 500 Гц.

Критерии текущей реализации:

```text
коэффициент: ±7 %
2 и 2000 Гц: ±10 %
6, 20, 1800 Гц: ±5 %
4000 Гц: затухание >= 20 дБ
```

Расчёт из В7:

```text
Q[pC] = C[pF] * Uin_vpp[V]
Uout_vpp = Vrms * 2 * sqrt(2)
Kmeas[мВ/пКл] = 1000 * Uout_vpp[V] / Q[pC]
```

# 11. В7 в ЯВП

Живой donor-прогон показал, что первая AC-точка может отвечать дольше 5 с:
при неизменной коммутации три попытки с 5000 мс завершились
`VI_ERROR_TMO`, а с 25000 мс результат пришёл за 7023 мс.

Поэтому production-профиль `master` использует:

```text
timeout_ms: 25000
MEAS:VOLT:DC?
MEAS:VOLT:AC?
MEAS:FREQ?
```

При timeout процедура делает VISA reconnect и повторяет чтение без смены
физического воздействия.

---

# 12. Safe stop ЯВП

Перед переходом и при исключении:

```text
Rigol OUTPUT OFF
  ↓
owner-scoped release маршрутов текущего YVP run
```

Сценарий разрешает активные команды только при явных:

```text
mapping_confirmed: true
active_outputs_confirmed: true
```

Donor `manual_confirmed` в `master` не используется: raw FAIL нельзя превращать
в OK, а отчёт не должен содержать искусственно сгенерированные измерения.

---

# 13. Свежесть данных

Для UDP-зависимых процедур общий принцип:

```text
before = last_sequence
  ↓
изменить физическое воздействие
  ↓
отбросить старое накопленное состояние
  ↓
ждать sequence > before
```

Новый verdict нельзя строить на кадре, который был получен до текущего
воздействия.

---

# 14. Граница полного покрытия

Текущая ЯВП-процедура физически проверяет 8 каналов. Исходное ТУ УБСИ требует
не менее 16 пьезоэлектрических каналов. Поэтому даже успешный 8-канальный
живой run не закрывает весь пункт количества каналов без подтверждённого
второго 8-канального тракта или иной документированной методики.

Кроме того, после переноса donor-тракта необходим актуальный полный живой run
`master`; unit-тесты fake equipment проверяют алгоритм, но не заменяют физическое
доказательство стенда.

---

# 15. Что сохраняется

После run сохраняются как минимум:

```text
run_id
scenario/version
profile/catalog version
steps
measurements
events
verdict
```

Production lifecycle связывает результат с изделием через registrar/run_id.
