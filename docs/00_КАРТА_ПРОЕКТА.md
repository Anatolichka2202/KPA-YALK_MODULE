# Карта проекта и принятые решения

Этот файл — краткая память проекта. При расхождении самописных документов с
этой картой сначала проверяется ТУ и живой стенд, затем обновляется карта.

## Назначение

`OrbitaDesktop` — единое стендовое приложение для аппаратуры с протоколом
«Орбита». `liborbita` принимает и дешифрует «Орбиту», сценарный движок
выполняет методику, а DLL-плагины управляют стендовым оборудованием.

Ближайший результат — полный УБСИ ЛВРМ.468157.002 по ТУ 5.6. БСИ является
следующим этапом и пока используется только для обкатки инфраструктуры.

## Тракты УБСИ

| Ячейка/задача | Воздействие | Источник результата |
|---|---|---|
| ЯЛК-96 | ИСД, эталон В7-78/1 | Ethernet/RS-485-адаптер |
| ЯТП | ручной магазин сопротивлений, ИСД | Ethernet/RS-485-адаптер |
| ЯВП-8 | Rigol, ИСД, контроль В7-78/1 | E20-10 + `liborbita` |
| ЯП-П | ИСД, нагрузочные цепи, В7-78/1 | В7 и состояние блока |
| питание блока | AKIP-1160/6 | AKIP и контроль связи |

Осциллограф не является обязательным для УБСИ 5.6. Р4831 не выдаётся за
автоматизированный прибор: оператор вручную выставляет сопротивление и вводит
фактическое значение, которое попадает в протокол.

## Где хранится настройка

- каталог/SQLite: `блок + ячейка + группа + канал → источник + адрес/слово +
  режим + семантический маршрут + смещение + подтверждение`;
- опубликованный сценарий: нормативная последовательность, точки, выдержки и
  допуски;
- профиль стенда: IP, порты, COM/VISA, реализация протокола и физические
  номера маршрутов ИСД.

Неподтверждённая привязка никогда не может сформировать приёмочный `OK`.
Ручной шаг может участвовать в `OK`, только если сохранены оператор, время,
задание и введённое фактическое значение.

В тракте УЛК есть как минимум четыре разных числовых сущности:

- номер ячейки/маршрута в команде KPA `адрЯЛК`;
- адрес измеряемого параметра УЛК в команде `УЛКтест`;
- позиция слова/поля в UDP-пакете адаптера;
- адрес параметра «Орбиты», который к ЯЛК УБСИ не относится.

Отчёт рабочей KPA показывает адреса параметров ЯЛК УЛК
`1–28, 32–43, 45–70, 74–87`, а сценарий калибровок — `97` и `99`.
Адрес `98` остаётся кандидатом для эталона 6,2 В и не считается
подтверждённым до живого отклика.

## Готовые наборы адресов «Орбиты»

В `orbita/config/address` уже находились рабочие текстовые списки, поэтому
для их консолидации не требуется захватывать обмен KPA. Скрипт
`scripts/consolidate_orbita_address_sets.ps1` бережно читает исходные файлы
Windows-1251, нормализует буквенные части адресов и создаёт:

- `ulk_slow.txt` — 46 медленных параметров УЛК;
- `ulk_fast.txt` — 16 быстрых параметров УЛК;
- `ulk_contacts.txt` — 13 контактных параметров УЛК;
- `ulk_all.txt` — 75 уникальных параметров для инженерского просмотра;
- `ULK_ADDRESS_REGISTRY.csv` — источник и количество адресов каждого набора.

Это наборы **мониторинга E20/«Орбиты»**, а не карта каналов адаптера
RS-485. Оператор или инженер может выбрать их в верхнем поле «конфиг», нажать
«Старт» и смотреть графики/таблицу. Сценарий УБСИ не берёт из `ulk_all.txt`
всё подряд: он разрешает только нужные параметры конкретной ячейки через
каталог и не даёт приёмочный `OK` при неподтверждённой привязке.
Эти адреса хранятся отдельно и не преобразуются в номер слова без
подтверждённой таблицы конкретного протокола адаптера.

## Сеть и текущая правда

- SSH ПЭВМ стенда: `192.168.0.31`, имя `DESKTOP-5EO9J5A`;
- проводной интерфейс ПЭВМ для оборудования: `192.168.0.50`;
- ИСД: `192.168.0.101`, HTTP отвечает;
- В7-78/1: `USB0::0x164E::0x0DAD::TW00053184::INSTR`, чтение работает;
- E20-10 открывается и читает АЦП, но в последней проверке `frames=0`;
- адаптер физически подключён; рабочая KPA исторически использует
  архивный вариант использует UDP `1001/1101` и протокол `ktma_firmware_udp_v1`,
  но IP адаптера в текущей конфигурации ещё
  не подтверждена живым ответом и захватом байтов команд;
- COM7 существует, его роль не установлена;
- рабочая KPA — референс фактически используемых команд и протокола, а не
  нормативный источник допусков.

История безопасных проверок находится в
