# MilTechStation · UI по поставкам и HMI-представлениям

**Дата:** 23 ноября 2026  
**Область работ этого потока:** только внешний вид, эргономика и логика взаимодействия пользователя с экранами MilTechStation.

## 1. Границы проекта UI

В этом потоке разрабатываем **пользовательское представление поставки**:
- навигацию полной станции и ограниченной ТУ-сборки;
- структурные экраны «Обзор», «Рабочая область», «Оборудование», «Сценарии», «Результаты»;
- наборы HMI-представлений, приборные панели и графики;
- сборку составного интерфейса из манифеста конкретной поставки;
- редактор мнемосхем / HMI с доступными элементами и каталогом источников на уровне UI;
- состояния без связи/данных, качество отображения и ошибки UX;
- компоновки, масштабирование, клавиатурные сценарии, разрешения экранов;
- прототип операторского ТУ-интерфейса, **не** создание ТУ EXE.

Задачи **вне данного потока**: исполнительное ядро, драйверы, протоколы, оборудование, конфигуратор сборки EXE, плагины, БД, Enterprise, учётные записи/роли и административный runtime. Эти задачи не проектируются заново в UI-коде.

Ранее созданные заглушки «Конфигуратор» и «Администрирование» сохранены в изолированном прототипе для совместимости с существующими композициями, но **в этом потоке не дорабатываются**.

## 2. Что значит «сборное HMI»

Одна поставка может содержать несколько **разных** HMI-представлений. Состав определяется декларативно.

```json
{
  "hmiPages": [
    { "id": "main", "title": "Изделие · обзор", "source": ":/ui/hmi/ktma.json" },
    { "id": "diagnostics", "title": "Мониторинг · диагностика", "source": ":/ui/hmi/ktma_diagnostics.json" }
  ]
}
```

Этот пример — действующий формат **UI Preview**, не production API `ProjectDefinition`. Файлы `hmi/ktma*.json` содержат *синтетические* шаблоны визуализации, а не технические характеристики измерений или схему физической коммутации.

### Реализованные UI-операции

| Место | Действие |
|---|---|
| Поставка / UI-манифест | подключить конкретные HMI-страницы и отдельные панели |
| HMI-представления | выбрать экран, создать, дублировать, переименовать, удалить |
| HMI-представления | редактировать элементы: текст, цифровые поля, статусы, шкалы, тренды, макеты команд |
| HMI-представления | переместить объект на сетке, задать геометрию и единицу, выбрать ключ данных |
| HMI-представления | выделение нескольких элементов Ctrl+Click/рамкой, визуальная группировка и разгруппировка, совместное перетаскивание |
| HMI-представления | выравнивание по 6 линиям, Ctrl+D — дублирование, Ctrl+Z / Ctrl+Shift+Z — история документа |
| HMI-представления | развёрнутый редактор (отдельное Qt-окно над той же моделью), выход Esc |
| HMI-представления | переключить редактор, пустой просмотр, синтетический просмотр |
| HMI-представления | сохранить/открыть отдельный экран JSON или весь комплект экранов |
| Рабочая область | переключить представление, синхронно перейти в то же представление в редакторе |
| Узкий экран | полосы инструментов разнесены по строкам, полный редактор доступен через прокрутку |

Ограничения `HmiDeliveryCollection`: до 12 HMI-страниц на поставку; нельзя удалить последнюю; при импорте требуется та же поставка, уникальные ID и корректный документ каждой страницы; неверный импорт оставляет предыдущий комплект. Это ограничения UI-прототипа, не эксплуатационные нормы.

### UX привязок к источникам

В инспекторе объекта доступны **два способа**: выбрать пример источника из выпадающего списка или указать ключ вручную. Демонстрационный каталог содержит четыре `ui.demo.*` ключа: напряжение, ток, уровень, дискретный статус.

Рядом с ключом показывается пояснение:
- **Совместим · синтетический источник** — тип элемента подходит к UI-фикстуре;
- **Тип источника несовместим с виджетом** — пример источника выбран, но его тип не соответствует статусу/шкале/графику;
- **Источник не разрешён · нет данных** — ключ неизвестен в текущей UI-фикстуре;
- **Источник не выбран · нет данных** — ключ отсутствует;
- **Команды заблокированы · нет API** — макет команды не вызывает железо.

Это только проверка **экранной семантики**. Связь с реальным параметрическим каталогом, качество данных, время измерения и реальные разрешения принадлежат отдельному проекту интеграции.

## 3. UX по поставкам

**КТМА / УБСИ**: несколько экранов (обзор изделия, диагностика) с различающимися UI-объектами; в рабочей области тот же набор, который настроен в редакторе. Полный технический паспорт реального оборудования из HMI-шаблонов не выводится и не подменяется демонстрационными данными.

**reference_device**: независимый набор HMI-экранов, другая композиция оборудования/представлений. Никакие специфические кнопки КТМА не должны появляться в данном контуре.

**ТУ / УБСИ**: только три операторских экрана: подготовка, испытание, результат. Внутри прототипа нет конструктора HMI, произвольного управления или административных компонентов.

## 4. Проверки пригодности

1. Структуру навигации можно изменять через UI-манифест без переписывания экрана `MainWindow`.
2. Выбранный экран HMI совпадает в редакторе и рабочей области.
3. Смена экрана не меняет состав другого экрана и не воздействует на прибор.
4. Добавление/дублирование/переименование/удаление, сохранение и импорт работают как UI-операции.
5. Документы другой поставки не импортируются и не смешиваются с текущими.
6. Число, статус, шкала и график различают отсутствие данных и демонстрационный источник.
7. Неверная привязка не превращается в нормальный статус.
8. В ТУ-представлении не появится редактор/инженерный экран из полной станции.
9. На 800×600, 1024×768, 1366×768, 1600×900 интерфейс остаётся доступным через адаптивное расположение и прокрутку.
10. У каждой будущей реальной кнопки управления будет отдельный источник разрешений и механизма команды — на UI-этапе их нет.

Сборка и offscreen-снимки доказывают компиляцию и визуальное состояние прототипа в CI, но не заменяют испытание UX на реальных рабочих местах, с мышью и клавиатурой.

## 5. Что остаётся именно по интерфейсу

- Более богатая палитра HMI (табличные каналы, пороговые диапазоны, группы, сложные диаграммы, специализированные контролы).
- Наглядный браузер будущих параметров и binding-инспектор с типом, единицей, источником и доступностью.
- Несколько рабочих пространств, профили компоновок и переключение HMI для разных экранов.
- Доработать профессиональный дизайнер: слои, блокировка объектов, распределение, клонирование стилей, привязка к линиям, горячие клавиши редактора, визуальные направляющие.
- Уточнение визуальных состояний ошибок, задержек данных, отрицательных результатов испытания.
- UX-ревью макетов с инженером и оператором на целевых мониторах.

### UX-ограничения редактора 0.6

- Группа — визуальная композиция объектов, не источник команд и не разрешение на действия.
- Undo/Redo хранится **в памяти отдельного HMI-документа**, не является журналом аудита. После повторной загрузки JSON история начинается заново.
- Компоновка полотна — фиксированные 960 × 540 логических пикселей. На 1366 × 768 часть редактора доступна с прокруткой, а для сложных мнемосхем предусмотрен развёрнутый режим.
- В превью значения только синтетические. Макеты команд по-прежнему заблокированы.
- Тесты CI включают смену поставки после работы с группами и полноэкранным окном, чтобы выявлять ошибки времени жизни Qt-сцен.

**Не следует объявлять эти будущие задачи завершёнными только потому, что есть Qt-виджеты.**
