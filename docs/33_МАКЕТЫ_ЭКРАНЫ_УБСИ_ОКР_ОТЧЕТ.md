# Макеты экранов УБСИ, регистрирующей машины и отчётности

Статус: спецификация браузерного прототипа  
Версия: 0.2  
Целевая область: desktop 1664×935, плотный industrial HMI

## 1. Первый вертикальный срез

В текущем макете испытатель видит только УБСИ. Основное окно сразу показывает выбранную процедуру; отдельного «домашнего экрана» внутри испытательного сеанса нет. В центре маршрута находятся измерения выбранного изделия, справа — этапы процедуры, снизу — безопасные действия.

```text
┌─ МилТех Станция · КТМА / УБСИ                         СТЕНД ГОТОВ ─┐
│ Изделие УБСИ-0241 · блок БСИ-042 · этап «После вибро»              │
│ [ ЯЛК-96 ]        [ ЯТП ]        [ ЯЛК-96 + ЯТП ]                  │
├───────────────────────────────────────────────┬────────────────────┤
│ измерения · график · таблица каналов          │ этапы и текущее    │
│                                               │ измерение          │
└─ ИТОГ · ПРОГРЕСС · ОТЧЁТ · БЕЗОПАСНО ОСТАНОВИТЬ · ЗАПУСТИТЬ ──────┘
```

## 2. Этапы жизненного цикла

| Этап | Что регистрируется | Доступный переход |
|---|---|---|
| 01 Разбор | состав блока, подключённые ячейки, первичные показания | к сборке после успешных ячеек |
| 02 Сборка | факт сборки, оператор, дата, комплектность | передать на вибро |
| 03 После вибро | возврат блока, повторные показания | к смоле/климату при `ОК` |
| 04 После климата | возврат, повторные показания, замечания | к облицовке при `ОК` |
| 05 Облицовка | факт облицовки и контроль комплектности | к финальной проверке |
| 06 Финал | все обязательные показания, паспорт, отчёт | закрыть объект |

Если ячейка не проходит проверку, создаётся карточка `ТРЕБУЕТ ЗАМЕНЫ`: блок остаётся тем же объектом, ячейка получает замену, а повторный запуск связывается с той же позицией.

## 3. УБСИ: этапы внутри процедуры

ЯЛК-96:

```text
готовность → ROKT init → 204-byte поток → ИСД 0 В
→ ИСД 3,10 В → ИСД 6,20 В → В7 + 16 fresh samples
→ калибровка 97 / 99 → обрыв/перегрузка → вердикт → сброс
```

ЯТП:

```text
готовность → ROKT 0A 02 → baseline 30 каналов
→ диалог Р4831: 0 Ом → диалог Р4831: 120 Ом
→ диалог Р4831: 240 Ом → 30 каналов → вердикт → сброс
```

ЯВП-8 и ЯП-П в операторском послесборочном маршруте УБСИ не показываются как обязательные проверки.

## 4. База ОКР

Экран `D · БД ОКР` — инженерский просмотр регистрирующей машины. Он не позволяет незаметно менять измерения.

### Панели

1. **Фильтр объекта**: заводской номер, блок, ячейка, этап, статус, период.
2. **Реестр объектов**: объект, текущий этап, последняя проверка, итог, открытые замены.
3. **Карточка объекта**: состав блока, история этапов и ответственные лица.
4. **Карточка ячейки**: источник данных, привязка, версии, все запуски и замены.
5. **Трассировка**: переход `объект → ячейка → запуск → измерение → отчёт`.

Минимальные поля реестра:

| Поле | Пример |
|---|---|
| Object ID | `KTMA-01-2026-009` |
| Block | `БСИ-42` |
| Cell | `УБСИ / ЯЛК-96` |
| Lifecycle stage | `После вибро` |
| Run ID | `1788531597977-a2504581` |
| Verdict | `ОК` / `НЕ ОК` / `НЕПОЛНАЯ` |
| Replacement | `нет` / `требуется` / `выполнена` |
| Report | `HTML · CSV · паспорт` |

## 5. Отчётность и паспорт

Экран `R · Отчётность` содержит два режима просмотра в одной рабочей области без вкладок: список запусков слева и выбранный документ справа.

Справа показываются:

- краткий протокол по ТУ;
- подробная ведомость каналов;
- график выбранного канала и обзор отклонений;
- источник каждого результата;
- версии сценария, каталога и профиля станции;
- события ручных операций;
- история этапов объекта;
- область паспорта с незаполненными нормативными полями до появления шаблона ОТК.

HTML и UTF-8 CSV остаются совместимыми с текущей машиной отчётности. PDF — отдельный слой оформления после утверждения шаблона ОТК.

## 6. Главное окно Станции и запуск КТМА

### Специализированная поставка КТМА

После загрузки ядра сразу открывает испытательный сеанс УБСИ. Промежуточный экран выбора не показывается, если в поставке доступна одна надстройка.

```text
МИЛТЕХ СТАНЦИЯ
ПОСТАВКА: КТМА · УБСИ
СТЕНД 01 · ГОТОВ

[ОТКРЫТЬ ИСПЫТАТЕЛЬНЫЙ СЕАНС УБСИ]
[F12 · АДМИНИСТРАТИВНЫЙ РЕЖИМ]
```

### Главное окно Станции (`S`)

В универсальной поставке показывает инфраструктуру ядра и запущенные надстройки:

- активные отдельные окна-сеансы;
- занятость оборудования и владелец каждого ресурса;
- активный профиль стенда;
- загруженные плагины КТМА;
- безопасное состояние выходов;
- очередь объектов и текущая ячейка;
- последнее событие и требуемое действие оператора.

Технические адреса и команды доступны только из инженерской диагностики.

## 7. Ручные формы

Формы делятся на операторские подтверждения и инженерские справочники.

Операторские:

- выбор объекта и ячейки;
- подтверждение этапа жизненного цикла;
- диалог сопротивления Р4831;
- подтверждение запуска;
- остановка и безопасный сброс.

Инженерские:

- профиль стенда;
- просмотр привязки из БД;
- черновик сценария;
- метаданные отчёта;
- допуски сотрудников, включая `Изменение состава`.

## 8. Визуальные состояния, которые должны быть в макетах

Для процедур ЯЛК-96, ЯТП и совместного прогона подготовить минимум пять состояний:

1. готовность;
2. выполняется;
3. требуется действие оператора;
4. неполная/ошибка;
5. остановлено безопасно.

В красном состоянии обязательно объяснять, что делать: например, `ЯТП · точка 120 Ом не подтверждена`, `ЯЛК · канал 57 вне допуска`, `адаптер не дал свежий кадр`. Одного красного цвета недостаточно.

## 10. Модель окон и режимов

- `Испытательный` режим работает в отдельном окне без бокового меню и не показывает YAML, плагины, БД или низкоуровневые адреса.
- `Административный` режим открывается по `F12` в отдельном окне. На текущем этапе дополнительной авторизации нет.
- Каждый испытательный сеанс является самостоятельным desktop-окном и владеет выделенным ему оборудованием.
- Жизненный цикл изделия редактируется в БД ОКР; в окне испытания он отображается кратко и не конкурирует с текущей процедурой.
- Внешние этапы вибрации и климата в минимальной поставке фиксируются вручную с возможностью приложить протокол; автоматическая интеграция оставлена на следующий этап.
