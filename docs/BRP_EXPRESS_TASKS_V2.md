## Актуальная база

- Стенд: `hardware/akip1160.*`, `hardware/isd_router.*`, `hardware/v7_meter.*`, `hardware/e2010_sample_source.*` — уже есть.
- Данные: `procedures/frame_checks.*`, `data/frame_checks.yaml`, декодер M16, RS-485-счётчик и вход ЯСМ `.bcfrm` — уже есть.
- Qt: `ui/brp_tu_window.cpp`, `ui/test_page.*`, `ui/tu_flow_widget.*`, `app/tu_report_writer.*` — уже есть.
- Ближайший источник прямых процедур: `rebuild/tu-minimal-clean`; `master` — отдельные приёмы для свежести, безопасного завершения и сохранения, **без копирования платформы**.
- Новое требование: **активная кнопка ББ ПР «Выдать сигнал»**. В проверенных исходниках подтверждено чтение `M16P1A10B60C21T01`, но не команда выдачи; маршрут надо подтвердить на стенде, не угадать.
- Новое требование: **PURUMK** как внешний источник сигнала для Манчестера. Интерфейс PURUMK в репозитории не найден. Ручной запуск из внешней программы допустим; автономная автоматизация необязательна.
- Ручной режим остаётся и может расширяться для трассировки. Проверить `BRP_ENABLE_MANUAL_TESTS=ON/OFF`.

## Вертикальные задачи

Каждый пункт — небольшой, демонстрируемый путь *от действия оператора до результата/журнала*, а не разработка нового слоя архитектуры. Приоритет P0 для рабочего БРП, P1 для ЯСМ.

### EXP-01 — Сквозной маршрут из уже реализованных проверок · P0
**Blocked by:** нет.

**Что получаем:** оператор запускает БРП ТУ, штатные источники и оборудование используются в нужном порядке, базовые интерфейсные проверки проходят без ручного запуска разрозненных диагностик, результат виден на экране.

**Приёмка:**
- [x] Сквозной маршрут на имитаторе: подготовка → питание → RS-485 → ИСД → измерения → завершение.
- [ ] Реальные команды АКИП через существующий драйвер. Для стендового прогона нужны утверждённые `voltage_v`, `current_limit_a` и `ovp_v` в `data/stand_brp.yaml`.
- [ ] Подтверждение безопасной остановки на стенде, в том числе при ошибке. В коде отчёт ждёт результата отключения АКИП, неподтверждённое отключение блокирует новый запуск.

**Проверка ПО.** `brp.scenario` сверяет события `POWER_ON` и `POWER_OFF` при штатном завершении и событие выключения после остановки оператором. В имитаторе используется программная модель питания. Полный CTest: 3/3 в Debug (ON), Release (ON) и Release (OFF).

### EXP-02 — Все выбранные адреса M16: свежесть и присутствие · P0
**Blocked by:** EXP-01 для подключения в общий маршрут; разработка алгоритма возможна независимо.

**Что получаем:** оператор видит отдельные результаты ПОС1–4, ПНА, ББ СУ/ПР, Ептм, Команда 1, Uск, резервы, Контроль стирания, Исправность и подтверждённых адресов датчиков. Проверка не подменяется одним старым значением.

**Приёмка:**
- [x] Адреса из текущей карты проверяются отдельно. Перечень задан в `data/frame_checks.yaml`.
- [x] Проверены два окна свежих групп. Одиночный краткий разрыв допускается, регулярные потери и повторы не дают НОРМА.
- [x] Выбранный инженерный монитор M8 не блокирует запуск формального ТУ M16.
- [x] `brp.frame_checks` покрывает непрерывный, повторяющийся, прерывающийся и отсутствующий поток.

Интеграция с программным маршрутом EXP‑01 подтверждена. Аппаратная приёмка маршрута ведётся в EXP‑01.

### EXP-03 — ПОС ±6 В: несколько точек с ЯФК/В7 · P0
**Blocked by:** EXP-01, EXP-02 (интеграция потока).

**Что получаем:** каждый ПОС проходит несколько точек по **±6 В**, видно реально заданное воздействие и измерения В7/M16, отдельный результат для каждой точки.

**Приёмка:**
- [x] Согласованная шкала **±6 В**; не заменять 0–3,3 В по тексту ТУ.
- [x] Повторно используются готовые алгоритмы сравнения, захвата и приборные команды.
- [ ] Не подтверждённая разводка ЯФК/В7 не считается измеренным успехом.
- [x] Приборная ошибка отдельно от отклонения БРП.

### EXP-04 — Дискретные воздействия + кнопка «ББ ПР — выдать сигнал» · P0
**Blocked by:** EXP-01; проверка соответствующих M16-значений использует EXP-02.

**Что получаем:** оператор нажимает кнопку ББ ПР для активной **выдачи** сигнала; подключённые дискретные входы переключаются через ИСД, неподключённые — с участием оператора. На экране видны результат команды, её снятие и наблюдаемая реакция.

**Приёмка:**
- [ ] Кнопка именно **выдаёт** сигнал по подтверждённому пути, а не просто показывает M16; при недоступном маршруте ясно объясняет причину и не выполняет ложное действие.
- [ ] Подтверждена физическая команда/маршрут ББ ПР (не предполагается из адреса M16).
- [ ] Подтверждённые дискретные воздействия через ИСД, `0/1` в свежих кадрах; ручной вариант с автопроверкой.
- [ ] Выдача, отключение и ошибка попадают в журнал; активные цепи не остаются без очистки.

### EXP-05 — Повтор, принудительный ОК и ошибки стенда · P0
**Blocked by:** EXP-01; для сводного отчёта используется EXP-06.

**Что получаем:** после НЕ НОРМА оператор выбирает «Повторить»/«Продолжить», успешный повтор даёт НОРМА без потери прежнего отказа. `Ctrl+Shift+Q` устанавливает ОК без преждевременного завершения; оборудование при ошибке останавливается безопасно и допускает повтор только после восстановления.

**Приёмка:**
- [ ] Все попытки сохранены с различимыми измерениями и действиями оператора.
- [ ] `Ctrl+Shift+Q` не завершает шаг досрочно; аппаратная ошибка не превращается в подтверждённый успех.
- [ ] Сбой стенда ≠ НЕ НОРМА БРП; повторяется только текущий шаг, предыдущие сохраняются.
- [ ] Тесты обеих кнопок, принудительного ОК и ошибки устройства.

### EXP-06 — Промежуточное сохранение, протокол и сборки ручного режима · P0
**Blocked by:** EXP-01 и EXP-05; экспорт кадрового шага опирается на EXP-02/03/04 по мере завершения.

**Что получаем:** результаты уже завершённых попыток доступны после закрытия приложения, отчёты соответствуют экранному итогу; ручная трассировка работает в текущей инженерной сборке и может быть исключена флагом.

**Приёмка:**
- [x] Принудительное завершение дочернего процесса имитатора до экспорта сохраняет завершённую попытку.
- [x] После перезапуска открывается история прерванной проверки. Новый прогон получает собственный файл, запись прежнего сохраняется побайтово.
- [x] TXT/HTML/CSV отражают измерения, неудачные попытки и принудительный результат. CSV отдельно показывает итог прогона.
- [x] `BRP_ENABLE_MANUAL_TESTS=ON` сохраняет ручную трассировку. В сборке `OFF` диагностического UI нет, основной маршрут проверен тестом `brp.scenario` (Release, CTest 3/3).

### EXP-07 — ЯСМ/Манчестер с внешней PURUMK · P1
**Blocked by:** EXP-01; не блокирует завершение EXP-02…06.

**Что получаем:** оператор готовит и запускает испытательный сигнал в **PURUMK**, приложение БРП выполняет уже существующий приём и сравнение ЯСМ, отображает вердикт и сохраняет его; при наличии подтверждённого интерфейса PURUMK возможен более автоматический вызов.

**Приёмка:**
- [ ] На рабочем стенде подтверждена связка PURUMK → сигнал → ЯСМ/«Орбита» → существующее сравнение M16.
- [ ] При отсутствии PURUMK показана причина, остальные проверки не блокируются.
- [x] Файл `.bcfrm`/образец проверяется штатным кодом, некорректная последовательность отличается от корректной.
- [ ] Без выдуманного CLI/API PURUMK и без фальшивого аппаратного ОК в симуляторе.

## Минимальные блокирующие зависимости

```
EXP-01 ─┬─ EXP-02 ─┬─ EXP-03
        │          └─ EXP-04 (для оценки M16; UI/команду можно делать параллельно)
        ├─ EXP-05 ── EXP-06
        └─ EXP-07 (P1, независимо от завершения P0)
```

**Параллелизм:** после EXP-01 EXP-02, EXP-05 и предварительный поиск интеграции PURUMK в EXP-07 можно вести независимо. В одном рабочем дереве нельзя одновременно править общие участки `brp_tu_window.cpp` без координации; разделение задач не обязывает создавать слои или новые фреймворки.

## Что сознательно НЕ является задачей

- Перенос/изменение MilTechStation и R/INT/UI Issues, полная перестройка классов, новый универсальный сценарный движок.
- Повторная реализация работающих драйверов АКИП, ИСД, В7, декодера M16, RS-485/ЯСМ.
- Обязательное участие M8 в формальном маршруте БРП.
- Отключение/удаление ручной трассировки в текущей инженерной сборке.
- Обещание физического сигнала ББ ПР или автоматизации PURUMK без проверенного оборудования и интерфейса.
