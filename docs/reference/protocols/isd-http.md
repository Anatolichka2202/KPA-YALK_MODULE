# HTTP-протокол ИСД

## Область

Этот документ относится к ИСД текущей поставки КТМА.

Endpoint:

```text
http://192.168.0.101
```

Это не общий API MilTechStation.

---

# Подтверждение команды

Текущая прошивка живого стенда подтверждает успешную команду коротким:

```text
OK
```

Текущая реализация также принимает старый текстовый ответ, содержащий:

```text
успешно
```

Это оставлено для совместимости со старой реализацией.

---

# Полный reset

Подтверждённая команда:

```text
/type=4num=1
```

Это штатный полный reset ИСД.

Нельзя подменять её перебором каналов `type=2`.

---

# Подготовка ЯЛК

После полного reset референсная программа выдерживает паузу:

```text
примерно 400 ms
```

Затем:

```text
/type=7num=1
```

Это текущая подтверждённая последовательность подготовки ЯЛК.

---

# Задание напряжения ЯЛК

Формат:

```text
/type=5num=<channel>val=<volts>work=1bus=1
```

Пример:

```text
/type=5num=47val=3.10work=1bus=1
```

Допустимый диапазон текущего adapter:

```text
0.00 ... 6.20 В
```

Значение задаётся в вольтах.

Не использовать старую трактовку:

```text
val=4095
```

как канонический способ задания аналоговой точки ЯЛК.

---

# Отключение выхода ЯЛК

Текущая безопасная последовательность:

## 1. Отключить bus

```text
/type=1num=<channel>val=0work=1bus=0
```

Затем:

```text
100 ms
```

## 2. Полностью выключить output

```text
/type=1num=<channel>val=0work=0
```

---

# Общая коммутация

Поддерживаемая форма:

```text
/type=<type>num=<channel>val=<0|1>
```

Конкретный `type` определяется подтверждённым физическим маршрутом.

Нельзя угадывать `type` для неизвестной коммутации.

---

# Общий raw analog route

В adapter существует форма:

```text
/type=1num=<channel>val=<value>work=<0|1>
```

Она является низкоуровневой возможностью.

Для стандартных точек ЯЛК использовать специализированный подтверждённый
`type=5` flow.

---

# ЯТП

Для физического тракта ЯТП подтверждена коммутация `type=7` каналов:

```text
3
9
12
17
```

Коммутация ИСД и команда запуска ROKT ЯТП — разные операции.

```text
ИСД
    готовит физический тракт

ROKT
    включает нужный поток адаптера
```

---

# HTTP transport

Текущая реализация:

- использует HTTP GET;
- проверяет HTTP status 2xx;
- проверяет содержимое ответа;
- для временных сетевых ошибок выполняет до трёх попыток;
- между временными ошибками выдерживает около 250 ms.

Ошибка HTTP является ошибкой стенда, а не дефектом проверяемого изделия.

---

# Безопасность

Активные команды ИСД должны выполняться только если текущая конфигурация
явно разрешает активные воздействия.

`safe_stop` плагина пытается выполнить полный reset ИСД.

Неподтверждённые физические маршруты нельзя активировать методом
перебора.
