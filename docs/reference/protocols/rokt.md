# ROKT — адаптер КТМА Ethernet / RS-485

## Статус

Этот документ описывает только последовательности, подтверждённые
референсной KPA и живым стендом.

# Endpoint текущей поставки КТМА

```text
adapter:
    192.168.0.115

UDP port:
    1113
```

Приём на Windows:

```text
bind:
    0.0.0.0:1113
```

Входящие datagram фильтруются по отправителю:

```text
192.168.0.115:1113
```

Это конфигурация текущей поставки КТМА, а не свойство общего
MilTechStation.

---

# Формат команд

Подтверждённые ROKT-команды текущего flow отправляются UDP datagram
длиной:

```text
128 байт
```

Начало:

```text
52 4F 4B 54
R  O  K  T
```

Неизвестные opcode не перебираются и не угадываются.

# Подготовка ЯЛК

Подтверждённая последовательность:

## 1. Reset

```text
byte 0..3 = "ROKT"
byte 4    = 0x16
остальные = 0
```

Затем пауза:

```text
50 ms
```

## 2. Адресация ЯЛК

```text
byte 0..3 = "ROKT"

byte 4 = 0x14
byte 5 = 0x01
byte 6 = 0x2B
byte 7 = 0x01
byte 8 = 0x00
```

Затем пауза:

```text
50 ms
```

## 3. Адресация ЯТП

```text
byte 0..3 = "ROKT"

byte 4 = 0x15
byte 5 = 0x01
byte 6 = 0x01
byte 7 = 0x01
byte 8 = 0x00
```

## 4. Запуск ЯЛК

```text
byte 0..3 = "ROKT"

byte 4 = 0x0A
byte 5 = 0x00
byte 6 = 0x00
byte 7 = 0x01
byte 8 = 0x00
```

---

# Кадр ЯЛК

После запуска ожидается свежий datagram:

```text
length = 204 bytes
header = 02 00 2B 00
```

Полезная часть:

```text
100 x uint16 little-endian
```

Слово:

```text
analog_code = raw & 0x03FF
contact      = (raw & 0x0400) != 0
```

Для текущей работы УБСИ используются только подтверждённые адреса и
калибровочные ячейки, описанные в документации УБСИ.

---

# Запуск ЯТП

Подготовка использует ту же подтверждённую последовательность reset +
адресация.

После подготовки текущая реализация выдерживает:

```text
500 ms
```

Затем:

```text
byte 0..3 = "ROKT"

byte 4 = 0x0A
byte 5 = 0x02
byte 6 = 0x00
byte 7 = endpoint number
byte 8 = 0x00
```

Для текущего стенда используется endpoint:

```text
1
```

То есть начало команды:

```text
ROKT 0A 02 00 01 00
```

`0x02` является подтверждённым wire-режимом ЯТП.

---

# Кадр ЯТП

Ожидается свежий datagram:

```text
length = 68 bytes
header = 01 00 34 00
```

Полезная часть:

```text
32 x uint16 little-endian
```

Назначение:

```text
words 1..30
    измерительные каналы

word 31
    верхняя калибровочная точка

word 32
    нижняя калибровочная точка
```

Значение:

```text
0x8000
```

означает отсутствие измерения и не интерпретируется как сопротивление.

---

# Свежесть кадра

После переключения режима или воздействия нельзя использовать кадр,
полученный до переключения.

Правило:

```text
зафиксировать текущий sequence
    ↓
выполнить переключение
    ↓
ждать frame.sequence > previous_sequence
```

Это особенно важно для длинных последовательностей ЯЛК и перегрузки.

---

# Stop

В текущей канонической документации не объявляется неподтверждённая
отдельная wire-команда STOP.

Runtime умеет остановить локальный UDP transport.

Безопасное выключение физического стенда обеспечивается общим
safe-stop сценарием оборудования, а не выдуманной ROKT-командой.

---

# Запрещённые старые трактовки

Не использовать старые неподтверждённые варианты запуска ЯТП вроде:

```text
ROKT 17 01
```

Канонический подтверждённый запуск ЯТП:

```text
ROKT 0A 02 00 <endpoint> 00
```

---

# Граница протокола

ROKT относится к поставке КТМА.

Он не является:

- API liborbita;
- протоколом «Орбита»;
- общим обязательным транспортом MilTechStation.
