# ROKT — адаптер КТМА Ethernet / RS-485

## Статус

Этот документ описывает только последовательности, подтверждённые референсной KPA и живым стендом/захватом. Неизвестные opcode, размеры и поля пакетов не угадываются.

Исследование:

[../../research/stand.md](../../research/stand.md)

---

# Endpoint текущей поставки КТМА

```text
adapter: 192.168.0.115
UDP port: 1113
receive bind: 0.0.0.0:1113
```

Входящие datagram фильтруются по отправителю `192.168.0.115:1113`. Это конфигурация текущей поставки КТМА, а не общее свойство MilTechStation.

---

# Формат команд

Подтверждённые ROKT-команды текущего flow отправляются UDP datagram длиной 128 байт и начинаются с:

```text
52 4F 4B 54
R  O  K  T
```

Неуказанные байты равны нулю.

---

# Подготовка ЯЛК

## Reset

```text
byte 0..3 = "ROKT"
byte 4    = 0x16
```

После команды выдерживается 50 ms.

## Адресация ЯЛК

```text
byte 4 = 0x14
byte 5 = 0x01
byte 6 = 0x2B
byte 7 = 0x01
byte 8 = 0x00
```

После команды выдерживается 50 ms.

## Адресация ЯТП

```text
byte 4 = 0x15
byte 5 = 0x01
byte 6 = 0x01
byte 7 = 0x01
byte 8 = 0x00
```

## Запуск ЯЛК

```text
byte 4 = 0x0A
byte 5 = 0x00
byte 6 = 0x00
byte 7 = 0x01
byte 8 = 0x00
```

---

# Кадр ЯЛК

После запуска ожидается свежий datagram:

```text
length = 204 bytes
header = 02 00 2B 00
```

Полезная часть:

```text
100 x uint16 little-endian
analog_code = raw & 0x03FF
contact     = (raw & 0x0400) != 0
```

---

# Запуск ЯТП

Подготовка использует ту же последовательность reset + адресация. После подготовки текущая реализация выдерживает 500 ms, затем отправляет:

```text
byte 4 = 0x0A
byte 5 = 0x02
byte 6 = 0x00
byte 7 = endpoint number
byte 8 = 0x00
```

Для текущего стенда endpoint = 1, то есть начало команды:

```text
ROKT 0A 02 00 01 00
```

`0x02` является подтверждённым wire-режимом ЯТП.

---

# Кадр ЯТП

Ожидается свежий datagram:

```text
length = 68 bytes
header = 01 00 34 00
```

Полезная часть:

```text
32 x uint16 little-endian
words 1..30 = измерительные каналы
word 31     = верхняя калибровочная точка
word 32     = нижняя калибровочная точка
```

Значение `0x8000` означает отсутствие измерения и не интерпретируется как сопротивление.

---

# ЯВП-8 — подтверждённые команды

Для ЯВП подтверждён отдельный ROKT-режим. Он не должен подменяться старой гипотезой чтения ЯВП как обычных адресов потока ЯЛК.

## Вход в режим ЯВП

```text
byte 0..3 = "ROKT"
byte 4 = 0x0A
byte 5 = 0x01
byte 6 = 0x00
byte 7 = cell number
остальные = 0
```

Для `cell = 1` начало команды:

```text
ROKT 0A 01 00 01
```

## Выбор одного из восьми каналов ЯВП

```text
byte 0..3 = "ROKT"
byte 4 = 0x0A
byte 5 = 0x03
byte 6 = channel - 1
byte 7 = cell number
остальные = 0
```

Допустимый физический номер канала: `1..8`; в byte 6 передаётся `0..7`.

## Граница подтверждения

На текущем этапе подтверждены:

```text
ROKT 0A 01 — вход в режим ЯВП
ROKT 0A 03 — выбор канала ЯВП 1..8
появление UDP-трафика после переключения
```

Не подтверждены и поэтому не фиксируются в этом reference как факт:

```text
размер/тип полезного кадра ЯВП
назначение полей кадра
масштабирование raw -> физическая величина
приёмочные критерии по декодированному кадру
```

До живого захвата и воспроизводимого декодирования ПО не должно выдавать приёмочное `НОРМА` по данным ЯВП. Для исследования используется `orbita_yvp_rokt_probe.exe`, который только переключает режим/каналы и сохраняет raw UDP.

---

# Свежесть кадра

После переключения режима или воздействия нельзя использовать кадр, полученный до переключения:

```text
зафиксировать текущий sequence
    ↓
выполнить переключение
    ↓
ждать frame.sequence > previous_sequence
```

Для ЯВП текущая ROKT-команда запускается через новый receiver, поэтому проверка подтверждает трафик, полученный уже после конкретной команды выбора режима/канала.

---

# Stop

В канонической документации не объявляется неподтверждённая отдельная wire-команда STOP. Runtime останавливает локальный UDP transport. Безопасное выключение физического стенда обеспечивает общий safe-stop оборудования.

---

# Запрещённые старые трактовки

Не использовать неподтверждённый запуск ЯТП `ROKT 17 01`; канонический запуск ЯТП — `ROKT 0A 02 00 <endpoint> 00`.

Не считать диапазон ЯЛК `88..96` доказанным wire-форматом ЯВП после того, как для ЯВП подтверждены собственные команды `0A 01` и `0A 03`.

---

# Граница протокола

ROKT относится к поставке КТМА. Он не является API liborbita, протоколом «Орбита» или обязательным транспортом общего MilTechStation.
