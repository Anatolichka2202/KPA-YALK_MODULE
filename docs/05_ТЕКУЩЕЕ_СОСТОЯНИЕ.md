# Текущее состояние

Дата среза: 26 августа 2026 года.

## Реализовано в `master`

- единый `OrbitaDesktop` с мониторингом «Орбита» и операторским экраном;
- явные режимы `Оператор` и `Инженер`; технические поля оборудования скрыты
  от оператора до открытия подробностей;
- версионируемый YAML-каталог и атомарный индекс SQLite;
- опубликованный YAML-сценарий УБСИ ЛВРМ.468157.002 по ТУ 5.6;
- сценарный движок с вложенными шагами и итогами `ОК / НЕ ОК / НЕПОЛНАЯ /
  ОШИБКА / ОСТАНОВЛЕНО`;
- стабильный C ABI Equipment SDK и динамическая загрузка DLL;
- плагины Ethernet-адаптера УБСИ, ИСД, В7-78/1, источника питания,
  DG-1022Z, Р4831 и Rigol DHO8xx;
- типизированные процедуры питания, 6,2 В, ЯЛК, ЯТП и ЯВП;
- встроенный источник `orbita.parameter_source`: сценарный движок получает
  живые данные E20/liborbita через тот же capability-контракт, что и DLL;
- диагностический сценарий подключённого БСИ, который проверяет цепочку
  `Орбита → сценарий → журнал → интерфейс` и всегда завершается `НЕПОЛНАЯ`;
- безопасный сброс оборудования после любого запуска и при остановке;
- журнал запусков SQLite, автономный HTML с графиком и UTF-8 CSV;
- инженерский YAML-редактор: опубликованный файл неизменяем, правка начинается
  с отдельного черновика;
- диагностический CLI плагинов и полный сборщик диагностики Windows 11;
- воспроизводимая упаковка выпуска Windows 11 в ZIP с SHA-256;
- модульные и интеграционные виртуальные тесты.

## Осознанно заблокировано до работы на стенде

В `data/profiles/stand_ktma.yaml` установлено
`active_outputs_confirmed: false`. Поэтому приложение не подаёт питание, не
коммутирует ИСД, не включает генератор и не переключает Р4831. Это не
недостающий код, а защита от непроверенной карты кабелей.

Перед первой аппаратной проверкой нужно по схеме А.1 подтвердить и записать:

- каналы ИСД для нагрузок 350/450 мА, ЯЛК и ЯВП;
- номера слов групп параметров Ethernet-адаптера;
- фактические IP/порты и VISA resources;
- что COM7 действительно управляет Р4831;
- команды и ограничения конкретного источника питания;
- активный набор адресов выходной телеметрии УБСИ для контроля потока Орбита.

После этого инженер меняет `TODO_CONFIRM`, устанавливает
`active_outputs_confirmed: true`, выполняет диагностику и только затем
разрешает полный запуск. До подтверждения доступен неполный диагностический
прогон; `ОК` из него получить нельзя.

Удалённая доставка подтверждена по Wi-Fi адресу ПЭВМ `192.168.0.31`.
Проводной адрес `192.168.0.50` нельзя использовать для SSH: он находится в
другой L2-сети с той же подсетью `192.168.0.0/24`.

## За пределами первой поставки

- проверки УБСИ 5.5 и климатические 5.7–5.8;
- полный опубликованный сценарий БСИ: подключённый БСИ сейчас используется
  только для обкатки общей инфраструктуры, приоритет поставки остаётся УБСИ;
- плагины ваттметра Я2М-66М и МБ26.20 — они не нужны УБСИ 5.6;
- аппаратная приёмка и метрологическое подтверждение повторяемости.

Старый `.scn`-интерпретатор и `ScenarioWizard` удалены из приложения. Delphi,
архивы прошивок и старые программы не являются исполняемой частью комплекса.
