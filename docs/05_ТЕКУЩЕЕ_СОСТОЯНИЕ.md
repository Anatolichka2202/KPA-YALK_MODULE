# Текущее состояние

Дата среза: 29 августа 2026 года.

## Реализовано в `master`

- единый `OrbitaDesktop` с мониторингом «Орбита» и операторским экраном;
- явные режимы `Оператор` и `Инженер`; технические поля оборудования скрыты
  от оператора до открытия подробностей;
- версионируемый YAML-каталог и атомарный индекс SQLite;
- разрешение каждого канала через БД: `блок + группа + канал → источник +
  адрес/слово + режим адаптера + семантический маршрут воздействия`;
- опубликованный YAML-сценарий УБСИ ЛВРМ.468157.002 по ТУ 5.6;
- сценарный движок с вложенными шагами и итогами `ОК / НЕ ОК / НЕПОЛНАЯ /
  ОШИБКА / ОСТАНОВЛЕНО`;
- стабильный C ABI Equipment SDK и динамическая загрузка DLL;
- плагины Ethernet-адаптера УБСИ, ИСД, В7-78/1, пары источников
  АКИП-1160/6, DG-1022Z и Rigol DHO8xx; Р4831 реализован как аудитируемая
  ручная операция, а не ложный COM-прибор;
- типизированные процедуры питания, 6,2 В, ЯЛК, ЯТП и ЯВП;
- встроенный источник `orbita.parameter_source`: сценарный движок получает
  живые данные E20/liborbita через тот же capability-контракт, что и DLL;
- безопасный сброс оборудования после любого запуска и при остановке;
- журнал запусков SQLite, автономный HTML с графиком и UTF-8 CSV;
- инженерский YAML-редактор: опубликованный файл неизменяем, правка начинается
  с отдельного черновика;
- диагностический CLI плагинов и полный сборщик диагностики Windows 11;
- воспроизводимая упаковка выпуска Windows 11 в ZIP с SHA-256;
- модульные и интеграционные виртуальные тесты.

## Аппаратно подтверждено 29.08.2026

### Ethernet/RS-485-адаптер и ЯЛК

Рабочая референсная KPA использует на `192.168.0.115:1113` четыре
128-байтные команды с сигнатурой `ROKT`, после которых адаптер передаёт
broadcast-кадры ЯЛК размером 204 байта (`4-byte header + 100 x uint16_t`).

Отдельный `orbita_ubsi_rokt_probe` воспроизвёл эту последовательность без KPA
и получил 16/16 кадров с header `02 00 2B 00` и стабильными значениями:

```text
ADDR 97: 124..125, median 125
ADDR 98: 920..921, median 921
ADDR 99: 922..923, median 922
```

Для этого 204-байтного формата подтверждено декодирование:

```cpp
analog = raw & 0x03FF;
signal = (raw & 0x0400) != 0;
```

Калибровка текущей методики использует адреса 97 и 99.

Архивный режим прошивки `44 01 06` также реален и даёт смешанный поток
4/120/200 байт, но это отдельный режим. Он не должен подменять рабочий тракт
референсной проверки `ROKT -> 204 bytes`.

### Windows UDP

Проверенная схема:

- receive bind: `0.0.0.0:1113`;
- command sender bind: `192.168.0.50:0`;
- адаптер передаёт `192.168.0.115:1113 -> 192.168.0.255:1113`.

Предыдущий bind receive-сокета непосредственно на `192.168.0.50:1113` не
подходил для broadcast в проверенной конфигурации Windows.

### В7-78/1

VISA resource:
`USB0::0x164E::0x0DAD::TW00053184::INSTR`.
Чтение напряжения работает.

### ИСД

Захват HTTP работающей KPA показал фактический протокол воздействия ЯЛК:

```text
/type=4num=1
/type=7num=1
/type=5num=1val=0.00work=1bus=1
/type=5num=1val=3.10work=1bus=1
/type=5num=1val=6.20work=1bus=1
```

Таким образом, точки ЯЛК задаются напряжением в вольтах через `type=5`, а не
кодом `0..4095` через `type=1`. Параметр `bus=1` входит в ту же команду и не
является отдельным `type=2`.

Ручное воспроизведение точки 6,20 В:

```text
/type=5num=1val=6.20work=1bus=1
```

дало на В7 три последовательных измерения:

```text
6.145045760 V
6.145045120 V
6.144935680 V
```

Следовательно, физический тракт ИСД -> линия ЯЛК -> В7 подключён и работает.
Нулевые показания прежних тестов были следствием неправильной команды ИСД,
а не отсутствия проводки.

Наблюдавшееся в KPA выключение канала:

```text
/type=1num=1val=0work=1bus=0
/type=1num=1val=0work=0
```

## Перенесено в production-код, аппаратный повтор ожидается

- транспорт адаптера раздельно поддерживает `legacy_mode6` (`44 01 06`,
  `Slow200`) и `rokt_yalk` (четыре 128-байтные команды, `Reference204`);
- `decodeYalkReferenceFrame` пропускает 4-байтный заголовок и декодирует 100
  little-endian слов масками `0x03FF/0x0400`, не затрагивая старый decoder;
- профиль стенда выбирает `rokt_yalk`, DLL читает свежие `Reference204` кадры;
- ИСД получил отдельные операции подготовки ЯЛК, задания напряжения через
  `type=5 ... bus=1` и подтверждённого двухкомандного выключения;
- `yalk_timing_probe` выполняет один канал production-классами: калибровка
  97/99, точки 0,00/3,10/6,20 В, В7 и 16 свежих значений адреса 1, затем сброс.

Локальная сборка и контрактные тесты пройдены 29.08.2026. Аппаратный прогон
этого production-контура переносится на следующий доступ стенда.

Запуск на стенде из корня проекта:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass `
  -File .\scripts\run_yalk_channel1_win11.ps1
```

Скрипт сохраняет полный вывод в `runs/diagnostics/yalk_channel1_*.log`.

Отдельно подготовлен полный диагностический цикл, не подключённый к
опубликованному сценарию: 80 рабочих адресов ЯЛК, три точки, В7, по 16 свежих
кадров, CSV и сырой поток. До аппаратного подтверждения соответствия
`канал ИСД = адрес УЛК` его результат называется только
`DIAGNOSTIC_OK/DIAGNOSTIC_FAIL`:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass `
  -File .\scripts\run_yalk_full_win11.ps1
```

Ближайшая контрольная точка — **один канал ЯЛК end-to-end**:

```text
ROKT init
-> 204-byte ЯЛК
-> ИСД 0 / 3.1 / 6.2 В через type=5, bus=1
-> В7
-> 16 свежих значений ЯЛК
-> калибровка 97/99
-> расчёт погрешности
-> вердикт
```

После одного устойчивого канала масштабировать на 80 рабочих адресов. UI и
отчёт не являются текущим блокером.

## ЯТП: commissioning-состояние на 02.09.2026

Добавлен отдельный опубликованный GUI/runtime-сценарий ЯТП на 30 каналов:
production-плагин выполняет ROKT-адресацию, отправляет
`ROKT 0A 02 00 01 00`,
принимает кадры `01 00 34 00 + 32 words` длиной 68 байт и пишет raw с
timestamp/sequence. Значение `0x8000` учитывается как `нет измерения`, а не Ом.
После восстановления отсутствовавшей аппаратной перемычки живой прогон дал
161/161 кадров: 30 рабочих слов находились в диапазоне `0x0879...0x087B`,
слова 31/32 — `0x0FA0` и `0x014A`. При постоянно установленном магазине
120 Ом двухточечный пересчёт дал `120,26...120,39 Ом`. Подтверждены команда
`ROKT 0A 02 00 01 00`, 30 рабочих слов, калибровки 31=240 Ом / 32=0 Ом и формула.
Сценарий просит оператора вручную подтвердить точки `0 / 120 / 240 Ом`,
проверяет допуск `±1,2 Ом`, строит график и формирует HTML/CSV. E20/Орбита и
нецелевые приборы для ЯТП не запускаются. ИСД выполняет подтверждённую
коммутацию `type=7` каналов `3/9/12/17` и обратное отключение при cleanup.

Магазин сопротивлений подключён к общему разъёму X123. ЯТП сама выбирает и
опрашивает 30 каналов; поканальный маршрут ИСД `ytp_channel` из каталога и
профиля удалён как ошибочная модель физического тракта.

Архивной прошивкой доказан отдельный legacy mode 2: команда `44 01 02`, кадр
65 байт, 30 рабочих little-endian слов, minimum/maximum и `TempMode`. Этот
декодер отделён от ЯЛК и не включается для текущего адаптера без явного
commissioning-подтверждения. Подробности и список требуемых живых фактов — в
`docs/20_ПРОВЕРКА_ЯТП.md`.

## Поставка проверки по ТУ на 04.09.2026

Живыми отчётами подтверждены полные трёхточечные прогоны ЯЛК и ЯТП. В
последнем намеренно разрегулированном прогоне ЯТП программа правильно выделила
3 ненормативных канала из 90 измерений.

В сценарии минимальной поставки добавлены повторное включение АКИП на
безопасной точке `27 В` с пределом `0,6 А`, чтение U/I, критерий тока
`≤ 0,4 А`, обязательное отключение питания и проверка остаточного напряжения
ЯЛК после сброса. Полный автоматический цикл 24/27/35 В и выдержка 19/37 В
ещё не являются выполненным объёмом ТУ.

После каждого запуска формируются два представления результата:

- краткий `Протокол_ТУ_*.html` по этапам и критериям;
- подробная `Ведомость_каналов_*.html/.csv` с raw, расчётными значениями,
  погрешностями и поканальными вердиктами.

Оператор подтвердил, что при замене БСИ на УБСИ соединение ИСД не меняется и
используется такая же ячейка ЯЛК-96. Поэтому отдельная «карта коммутации УБСИ»
не требуется. Из референсного `10_ЯЛК_перегрузки.scn` перенесены проверка
обрыва по сигнальному биту и последовательность перегрузки: пилообразный фон
на физических каналах 1–88, маршрут 96 для +12 В, маршрут 95 для -12 В и
контроль неизменности остальных 87 адресов в пределах 0,5 % полной шкалы.
Реализация прошла автоматические тесты; воздействие ±12 В ещё должно быть
проверено живым прогоном. ЯВП-8 стендом не измеряется и в совмещённом кратком
протоколе может быть указан только как принятый по отдельному производственному
контролю.

## Операторская поставка УЛК на 02.09.2026

Операторский UI сужен до трёх маршрутов: ЯЛК-96, ЯТП и последовательный
ЯЛК+ЯТП. Старые режимы всего блока, БСИ, АКИП, Rigol, E20 и прочих ячеек в
операторском экране не показываются. Адаптер и ИСД видны постоянно как статус
тракта; В7 показывается для ЯЛК, ручной Р4831 — для ЯТП.

Поканальные измерения поступают в таблицу и живой график. Для ЯТП/120 Ом
используется увеличенная шкала 116..124 Ом; в совмещённом режиме ЯЛК и ЯТП
сопоставляются по общей приведённой шкале `% FS`. После каждого запуска
автоматически формируются HTML и CSV, доступные кнопкой `Открыть отчёт`.
