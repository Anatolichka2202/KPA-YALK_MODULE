# Границы проекта

Это базовая модель, по которой разделяется вся документация.

```text
УРОВЕНЬ 0
РЕПОЗИТОРИЙ
    │
    ├───────────────┐
    │               │
    ▼               ▼
УРОВЕНЬ 1        реализация конкретной
ПРОДУКТ          поставки
MilTechStation
    │
    ▼
УРОВЕНЬ 2
ПОСТАВКА
КТМА
    │
    ▼
УРОВЕНЬ 3
ТЕКУЩИЙ ОБЪЕКТ
УБСИ
```

---

## 0. Репозиторий

Репозиторий содержит больше, чем один программный продуктовый слой.

Здесь совместно находятся:

- общие механизмы MilTechStation;
- реализации для поставки КТМА;
- текущая работа по конкретному объекту поставки;
- исполняемые сценарии и конфигурации;
- исследования;
- первичные технические материалы.

Поэтому наличие кода или файла в репозитории само по себе не означает,
что он является частью общего продукта MilTechStation.

---

## 1. Продукт: MilTechStation

MilTechStation — программная платформа автоматизированной испытательной
станции.

Продукт предоставляет общие механизмы, которые могут использоваться
разными поставками и разными объектами испытаний.

К продуктовому уровню относятся, например:

- выполнение сценариев испытаний;
- подключение оборудования через плагины;
- общая модель результата испытания;
- регистрация результатов;
- безопасное управление выполнением;
- общая инфраструктура операторского приложения;
- программные API и ABI общего назначения.

Продукт не должен знать требования конкретного УБСИ, если они не являются
общими возможностями платформы.

Подробнее:
[MilTechStation](product/miltechstation.md).

---

## 2. Поставка: КТМА

КТМА — конкретная поставка, построенная на MilTechStation.

Поставка определяет конкретную конфигурацию станции:

- состав испытательного оборудования;
- используемые интерфейсы;
- сетевые подключения;
- поддерживаемые изделия;
- конкретные сценарии;
- конкретные нормативные документы;
- формы производственной отчётности;
- правила эксплуатации данной установки.

То, что необходимо КТМА, не обязано становиться общей возможностью
MilTechStation.

Подробнее:
[КТМА](delivery/ktma.md).

---

## 3. Текущий объект: УБСИ

УБСИ — текущий объект работ внутри поставки КТМА.

На этом уровне находятся:

- требования к УБСИ;
- рабочая выжимка из ТУ;
- методики проверки УБСИ;
- особенности трактов УБСИ;
- сценарии испытания УБСИ;
- операторский процесс УБСИ;
- результаты исследований, относящиеся к УБСИ;
- текущее покрытие автоматизацией.

Решение, принятое только для УБСИ, нельзя автоматически считать правилом
всей КТМА или всей MilTechStation.

Подробнее:
[УБСИ](task/ubsi.md).

---

# Правило продвижения по объектам

Пока УБСИ не закрыт, он является текущим объектом проекта.

Агент не должен заранее загружать в рабочий контекст технические
подробности других изделий.

После явной фиксации, что УБСИ закрыт:

1. итоговые знания УБСИ остаются в документации;
2. `PROJECT_MEMORY.md` очищается от лишней оперативной детализации УБСИ;
3. в `task/` выбирается следующий текущий объект;
4. агент начинает загружать документацию нового объекта.

# Проверка правильности размещения знания

Перед добавлением информации спросить:

**Это верно для любого MilTechStation?**

Если да:

```text
docs/product/
```

Если нет:

**Это верно для всей поставки КТМА?**

Если да:

```text
docs/delivery/
```

Если нет:

**Это относится только к текущему УБСИ?**

Если да:

```text
docs/task/
```

Если это результат эксперимента или анализа:

```text
docs/research/
```

Если это первичный внешний документ:

```text
docs/sources/
```

Если это знание про объект, который сейчас не находится в работе:

```text
docs/notes/
```

# Главное ограничение

Документ более высокого уровня не должен постепенно превращаться в
свалку деталей нижних уровней.

Вверх переносится только действительно общее правило.
