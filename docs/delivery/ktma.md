# Поставка КТМА

## Что это

КТМА — конкретная поставка, реализуемая на базе MilTechStation.

Репозиторий исторически содержит много знаний именно о КТМА, поэтому
особенно важно не принимать любую найденную реализацию за общее правило
продукта MilTechStation.

---

## Место в системе

```text
MilTechStation
      │
      └── КТМА
            │
            └── текущий объект: УБСИ
```

---

## Что определяет поставка

На уровне КТМА определяются:

- конкретный состав стенда;
- способы подключения оборудования;
- конкретные протоколы оборудования;
- поддерживаемые изделия;
- сценарии испытаний;
- нормативные исходные данные;
- структура производственного документооборота;
- конфигурация рабочих мест;
- правила развёртывания и эксплуатации поставки.

---

## Используемые технические механизмы

В текущей поставке используются, в частности:

### Данные «Орбита»

Для декодирования данных протокола «Орбита» используется `liborbita`.

### Адаптер RS-485 / Ethernet

Для связи с частью оборудования используется Ethernet/RS-485 адаптер с
протоколом ROKT.

Подробный подтверждённый протокол будет находиться в:

```text
docs/reference/protocols/rokt.md
```

### Лабораторное оборудование

Управление лабораторным оборудованием выполняется через плагины.

В зависимости от прибора используются:

- VISA;
- SCPI;
- LAN;
- HTTP.

### ИСД

ИСД в текущей поставке использует HTTP-интерфейс.

Подтверждённые команды ИСД будут вынесены в отдельный
protocol-reference.

Сейчас основной объект работ КТМА:

**УБСИ**.

Пока УБСИ не закрыт, документация других изделий не должна попадать в
стартовый контекст агента.

Подробнее:

[Текущий объект УБСИ](../task/ubsi.md)

---

## Другие изделия

Репозиторий может содержать исторический код, заметки и материалы по
другим изделиям КТМА.

Эти знания:

- не удаляются автоматически;
- не считаются текущим рабочим контекстом;
- не загружаются агентом без явной задачи;
- во время миграции переносятся в `docs/notes/`.

В частности, сведения о БСИ не должны автоматически использоваться при
работе над УБСИ.
