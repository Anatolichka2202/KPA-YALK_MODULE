# Модель КТМА и состав изделия

КТМА рассматривается как жизненный цикл изделия, а не как один запуск
`OrbitaDesktop`. Блок имеет состав, состав состоит из установленных ячеек, а
каждая попытка этапа ссылается на конкретный `run_id` стенда.

## Объекты

```text
Product (изделие/SN)
  └─ ComponentBinding (тип ячейки + SN + active/removed)
       └─ StageAttempt (ячейка + этап + verdict)
            └─ StageRun (stage_attempt_id → run_id в runs.db)
```

Регистратор не копирует подробные измерения: они остаются в `runs.db`. Он
хранит только трассируемую связь, состав и итог.

## Обязательные этапы

| Код | Смысл |
|---|---|
| `InitialElectrical` | входная электрическая проверка до воздействий |
| `PostVibrationElectrical` | повтор после вибрации |
| `PostClimateElectrical` | повтор после климатического воздействия |
| `FinalElectrical` | финальная электрическая проверка перед выпуском |

Климат и вибрация выполняются отдельной технологической операцией. После
возврата изделия на стенд запускается обычный сценарий соответствующего этапа;
стенд не моделирует климатическое воздействие.

## Правило замены

```text
YALK SN-001 FAIL
  → removeComponent(reason)
  → installComponent(YALK SN-002)
  → четыре этапа SN-002 заново
```

Снятая SN никогда не удаляется. Она видна в истории с временем, причиной и
своими неуспешными попытками.

## Вердикты

- `Ok` — все требуемые этапы активной ячейки завершены успешно;
- `Fail` — хотя бы один завершённый обязательный этап активной ячейки не прошёл;
- `Incomplete` — состав пуст, этап пропущен или ещё выполняется;
- `Cancelled` — оператор остановил этап; для итогового выпуска это не PASS;
- `InProgress` — промежуточное состояние.

Итог КТМА вычисляется только по активным ячейкам. Любая обязательная замена
создаёт новый цикл, поэтому PASS старой SN не переносится на новую.

## Границы текущей реализации

`ktma_registrar` уже предоставляет CRUD изделия/ячеек, установку и снятие,
этапы по ячейке, привязку запуска и вычисление итога. Полноценный операторский
экран регистратора подключается поверх этого API; сценарии стенда остаются
независимыми и могут запускаться без Qt UI.
