# Референсные программы и доказательства

Для спорного протокола используется порядок доверия:

```text
ТУ/методика → живой захват KPA_Rokot → архивные исходники → текущая реализация
```

| Референс | Путь | Доверие | Подтверждает | Нельзя выводить |
|---|---|---|---|---|
| KPA_Rokot | `KPA_Rokot.exe` (SHA-256 `BA14F393883B1EE19C8B142ADE1949B2F155DC8FD0DDDF9FDEAF9A21D0C1C35E`) | live_reference | последовательность ROKT, длины кадров, порядок cleanup | что архивный режим совпадает с текущим |
| Orbita | `orbita/`, `liborbita` | implementation/reference | декодирование потока и адресные параметры | карту физической коммутации |
| ИСД | `stand/plugins/isd_http_plugin.cpp`, захваты HTTP | live_reference | type=5 в вольтах, `bus=1`, type=7/type=4 | что ИСД программирует сторонний прибор |
| RS-485 адаптер | `stand/plugins/ktma_adapter_udp_plugin.cpp`, `stand/adapters/ulk_udp_transport.cpp` | implementation + live capture | UDP/ROKT transport, broadcast bind | приёмочные карты незакрытых ячеек |
| V7 | `stand/plugins/v7_visa_plugin.cpp`, `stand/adapters/v7_visa_voltmeter.cpp` | hardware_verified | фактическое эталонное напряжение | значения телеметрии без измерения |
| Delphi/сценарии | `KPA_Rokot_ascii.txt`, `KPA_Rokot_utf16.txt`, `scripts/*.scn` | historical/reference | названия шагов и диагностические подсказки | нормативный допуск без ТУ |
| Захваты | `stand_captures/`, `captures/`, `kpa_reference/` | evidence | байтовые кадры конкретного прогона | универсальность вне той прошивки |

## Закреплённые wire-факты

- ЯЛК: четыре 128-байтные ROKT-команды, затем broadcast 204 байта;
- ЯТП: `ROKT 0A 02 00 01 00 ...`, затем broadcast 68 байт;
- архивный `44 01 06` остаётся отдельной веткой и не заменяет текущую KPA;
- UDP receive bind — `0.0.0.0:1113`, sender — `192.168.0.50:0`;
- команды ИСД для аналоговой точки передаются в вольтах через `type=5` с
  `bus=1`.

## Как обновлять запись

Для нового бинарника или захвата фиксируются путь, версия/дата, SHA-256, среда,
что именно было измерено, и список выводов, которые запрещены. Если живой
стенд расходится с архивом, production-код сначала повторяет живой обмен, а
архив сохраняется как историческая справка.
