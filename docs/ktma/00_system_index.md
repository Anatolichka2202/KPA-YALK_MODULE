# КТМА: канонический индекс системы

Этот каталог — короткая память проекта для инженера и агента. Здесь фиксируется
модель предметной области, границы доказанности и точки входа в код. Первичные
ТУ, захваты и бинарники не заменяются этим индексом; они используются только
для проверки спорных утверждений.

## Термины

- **КТМА** — комплекс, в котором изделие проходит жизненный цикл и получает
  итоговый производственный вердикт.
- **БСИ/УБСИ** — проверяемые блоки. Блок состоит из ячеек и внешних трактов;
  ячейка не равна каналу телеметрии.
- **ЯЛК-96** — аналоговая ячейка УБСИ. Воздействие задаёт ИСД, эталон снимает
  В7-78/1, коды текущей референсной проверки приходят через RS-485/ROKT.
- **ЯТП** — температурная ячейка УБСИ. Магазин Р4831 подключён к общему X123,
  оператор вручную выставляет сопротивление, а ЯТП сама опрашивает 30 каналов.
- **ЯВП-8/ЯП-П/ЯФК** — другие ячейки БСИ/УБСИ. Их карты и методики пока не
  позволяют выдавать приёмочный результат автоматически.
- **Орбита** — формат потока и `liborbita`; это не название общего стендового
  продукта.

## Общая несущая конструкция

```text
ТУ/методика → каталог и профиль → ScenarioEngine → capability оборудования
                                      ↓
                              run_id / события / измерения
                                      ↓
                         отчёт запуска → отчёт ячейки → журнал КТМА
```

Код разложен по ролям: `liborbita` декодирует поток, `stand_core` исполняет
сценарии, `stand_io` общается с приборами, каталог разрешает адреса и маршруты,
а `registrar` ведёт состав изделия и этапы. Операторский UI только запускает
сценарий и показывает его состояние.

## Три базы

| Файл | Роль | Что нельзя делать |
|---|---|---|
| `parameters.db` | адреса, каналы, режимы и подтверждённые маршруты | хранить историю запусков |
| `runs.db` | raw, события, измерения и вердикт конкретного прогона | использовать как реестр изделия |
| `registrar.db` | изделие, ячейки, замены, этапы и ссылки `run_id` | удалять старую ячейку после FAIL |

## Статусы доказанности

`verified` — подтверждено ТУ и живым стендом; `partial_verified` — рабочая часть
подтверждена, покрытие неполное; `diagnostic_only` — только диагностика;
`not_verified` — карта или методика отсутствует. Неподтверждённый маршрут не
может сформировать приёмочный `НОРМА`.

## Жизненный цикл ячейки

```text
InitialElectrical → PostVibrationElectrical → PostClimateElectrical
                  → FinalElectrical
```

При FAIL снимается только соответствующая ячейка с обязательной причиной,
старая запись остаётся в истории, устанавливается новая SN и четыре этапа для
неё начинаются заново. Итог блока: `НОРМА` только при PASS всех активных ячеек;
`НЕПОЛНАЯ` при пропущенном/открытом этапе или пустом составе; `НЕ НОРМА` при
окончательном FAIL.

## Приоритет источников

```text
ТУ/методика → живой стенд и KPA_Rokot → архивная прошивка → текущий код
```

Архивный режим `44 01 06` сохраняется как отдельная историческая ветка. Для
текущего стенда ЯЛК используется подтверждённый ROKT-путь с кадром 204 байта,
для ЯТП — `ROKT 0A 02 00 01 00` и кадр 68 байт.
