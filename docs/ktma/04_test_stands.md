# Стенды и обмен с оборудованием

Профиль стенда хранится в `data/profiles/stand_ktma.yaml`; в нём находятся
адреса, порты, VISA/COM и физические маршруты. Каталог хранит смысловую
привязку канала, а не настройки сети.

## Подтверждённая сеть

| Узел | Адрес/ресурс |
|---|---|
| ПЭВМ | `192.168.0.50/24` |
| RS-485/ROKT адаптер | `192.168.0.115:1113` |
| ИСД | `192.168.0.101:80` |
| В7-78/1 | `USB0::0x164E::0x0DAD::TW00053184::INSTR` |

Приём UDP должен bind-иться на `0.0.0.0:1113`, команды отправляются с
`192.168.0.50:0`, кадры фильтруются по отправителю `.115:1113`. Адаптер
передаёт broadcast на `.255:1113`.

## Capability-контракты

Сценарий требует абстрактные возможности, например:

| Capability | Реализация |
|---|---|
| `ulk.parameter_source` | UDP/ROKT адаптер или встроенный источник потока |
| `stand.switch_matrix` | HTTP/ИСД и стендовая коммутация |
| `measure.reference_voltage` | VISA В7-78/1 |
| `power.dc_supply` | DLL-плагин АКИП-1160/6 |
| `catalog.parameter_resolver` | `parameters.db` |
| `operator.manual_input` | подтверждаемая ручная операция Р4831 |

Такой контракт позволяет подменить прибор fake-capability в тесте и использовать
один сценарий УБСИ в инженерском и операторском UI.

## Жизненный цикл питания

Сначала мастер включает АКИП. Проверка оборудования читает питание и
подключаемый адаптер в правильном порядке; отключение АКИП выполняется только в
cleanup после завершения потока. Любая ошибка, отмена или исключение вызывает
`safeStopAll`, выключение воздействий и безопасное состояние маршрутов.

## Где находится код

- `stand_core` (`orbita_stand_core`) — типы сценария, вердикты, события и
  `ScenarioEngine` без Qt UI и приборов;
- `stand/src/ubsi_procedures.cpp` — предметные процедуры УБСИ;
- `stand/adapters` и `stand/plugins` — I/O и DLL SDK;
- `stand/src/catalog.cpp`, `config.cpp` — каталог и профиль;
- `stand/src/run_store.cpp`, `report_writer.cpp` — запуск и отчёт;
- `desktop_orbita` — оболочка операторского/инженерского UI;
- `registrar` — отдельная SQLite-библиотека жизненного цикла.

Разделение выполняется постепенно: старые target-имена сохраняются ради
совместимости текущей ZIP-поставки.
