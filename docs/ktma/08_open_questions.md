# Зафиксированные решения и задачи реализации

Открытых методических вопросов по текущей поставке УБСИ нет.

Все решения по объёму проверки, режимам работы, ЯЛК, ЯТП, ЯВП, перегрузкам, ручным операциям, повторным попыткам и отчётности приняты.

Ни один пункт ниже не является вопросом к производству или главному инженеру. Оставшиеся позиции являются только задачами реализации, конфигурации или проверки на живом стенде.

## УБСИ

### ЯЛК

Принято:

```text
аналоговые точки:
0 / 3,1 / 6,2 В

контактные точки:
0 В   → 0
0,9 В → 0
2,5 В → 1

проверяются все рабочие каналы
```

ИСД задаёт воздействие.

В7 измеряет фактическое напряжение и является эталоном.

ЯЛК формирует raw-код.

Результат читается из 204-байтного потока адаптера.

Для пересчёта используются калибровочные значения 97 и 99.

В результат сохраняются:

```text
code97
code99
raw-код канала
показание В7
пересчитанное значение ЯЛК
погрешность
```

### Обрыв

Проверяются все аналоговые входы.

Воздействие выполняется последовательно.

Длительность хранится в конфигурации.

Значение по умолчанию:

```text
10 с
```

Признак обрыва определяется экспериментально на живом стенде и после определения фиксируется в конфигурации/коде.

Это задача наладки, а не открытый методический вопрос.

### Перегрузка ±12 В

Проверка принята.

Каждый вход проверяется последовательно:

```text
+12 В
-12 В
```

Длительность воздействия:

```text
по умолчанию 10 с
```

Длительность должна быть конфигурируемой.

Во время перегрузки контролируется работоспособность остальных входов.

Дополнительного согласования этой методики не требуется.

## ЯТП

Методика принята полностью.

```text
Р4831 — ручной магазин
общий вход X123

точки:
0 Ом
120 Ом
240 Ом

каналов:
30
```

Оператор вручную устанавливает значение Р4831 и подтверждает операцию.

Программа считывает все 30 каналов ЯТП.

Линия термодатчика 50 м в текущей проверке не применяется.

## ЯВП

Методика принята.

Генератор:

```text
Rigol DG-1022Z = ДГ10.2
```

Физический тракт:

```text
Rigol DG-1022Z
→ конденсатор 1000 пФ
→ вход ЯВП
→ ЯВП
→ ЯЛК
→ UDP 204 байта
→ стендовое ПО
```

ИСД:

```text
выбирает вход ЯВП
выбирает коэффициент через контакты X1
```

Выходы ЯВП на УБСИ читаются через каналы ЯЛК:

```text
89–96
```

Коэффициенты:

```text
0,25
0,5
1
2
4
8
32 мВ/пКл
```

Амплитуды генератора:

```text
K = 0,25 → 8 В
K = 0,5  → 4 В
K = 1    → 2 В
K > 1    → 1 В
```

Частотные точки:

```text
0,15 Гц
20 Гц
250 Гц
500 Гц
1800 Гц
2000 Гц
4000 Гц
```

В7 измеряет фактические частоту и напряжение входного сигнала.

Результат ЯВП определяется через выход ЯЛК.

Расчёт:

```text
Q[пКл] = C[пФ] × Uвх[В]

Kизм[мВ/пКл] =
1000 × Uвых[В] / Q[пКл]

δK[%] =
(Kизм − Kзад) / Kзад × 100
```

Критерий быстроменяющегося параметра:

```text
±7 %
```

АЧХ:

```text
ΔАЧХ[%] =
(A(f) / Aref − 1) × 100
```

Затухание:

```text
D[dB] =
20 × log10(Aref / A(f))
```

Оставшиеся действия по ЯВП:

```text
определить реальные команды ИСД;
закрепить соответствие каналов 89–96;
проверить фактический масштаб тракта;
проверить режимы K=8 и K=32;
настроить VISA resource генератора;
реализовать последовательность в ubsi.yvp;
проверить методику на живом стенде.
```

Это задачи реализации и стендовой верификации.

Они не являются открытыми вопросами.

## Питание датчиков 6,2 В / 350–450 мА

Проверка ручная.

Для текущей поставки она в программный сценарий не входит.

В будущем программа может после автоматической проверки предоставить оператору отдельную форму ручной проверки.

Для текущей поставки:

```text
manual_sensor_supply_check = disabled
```

Отсутствие этой формы не влияет на автоматический результат текущей поставки.

---

## Эталон 6,2 ±0,03 В — п. 1.1.4.9

Решение принято.

```text
ИСД задаёт воздействие
В7 измеряет фактическое значение
ЯЛК формирует код
204-байтный поток адаптера используется как выходная телеметрия УБСИ
```

Уставка ИСД сама по себе эталоном не является.

Требование покрывается существующим трактом ЯЛК.

---

## Входной ток ≤2 мкА

Отдельное стендовое измерение не выполняется.

В документации и отчёте:

```text
Обеспечивается конструкцией кросс-платы
в нормальных условиях.
```

Фиктивное измерение не создаётся.

---

## Сопротивление изоляции

В текущую проверку не входит.

Не проверяется.

Не является открытым вопросом.

Не должно появляться в автоматическом сценарии и не должно блокировать результат текущей проверки.

---

## Повтор технических ошибок

Принято:

```text
до трёх автоматических повторов
```

Повтор выполняется при технически несостоявшемся измерении:

```text
таймаут
ошибка связи
ошибка оборудования
невалидный кадр
ошибка состояния стенда
```

После исчерпания повторов:

```text
ОШИБКА СТЕНДА
```

Это не `НЕ НОРМА` изделия.

Независимые части проверки продолжаются.

---

## Статусы

Для отдельного нормативного пункта:

```text
НОРМА
НЕ НОРМА
ОШИБКА СТЕНДА
```

Для общего запуска дополнительно:

```text
НЕПОЛНАЯ ПРОВЕРКА
```

`НЕПОЛНАЯ ПРОВЕРКА` используется только как агрегатный итог, когда невозможно определить полный результат изделия из-за технической ошибки стенда.

## Ручные действия

Р4831 и другие предусмотренные ручные операции подтверждает оператор.

Оператор и время подтверждения сохраняются вместе с запуском.

---

## Отчёт

Программа:

```text
формирует итоговый протокол;
сохраняет результаты в БД;
предоставляет протокол на печать.
```

Что происходит с напечатанным документом дальше — вне ответственности ПО.

---

## Производство

Производственный режим хранит:

```text
изделие
серийный номер
состав ячеек
SN каждой ячейки
этап
результаты
run_id
ремонт
замену
историю повторных испытаний
```

При ремонте или замене повторяются все проверки, относящиеся к этой ячейке и её выходам.

История старой ячейки не удаляется.

---

## Приёмка

Приёмо-сдаточный режим является самостоятельным полным прогоном текущей методики.

Он не зависит от состояния производственного маршрута.

Оператор видит минимум информации:

```text
изделие
ход проверки
необходимое ручное действие
результат
```

Инженерные подробности скрыты.

---

## БСИ

БСИ не является блокером УБСИ.

Принято:

```text
ЯЛК — та же методика, что в УБСИ
ЯТП — та же методика, что в УБСИ
ЯВП — та же методика, что в УБСИ

ЯФК используется для получения телеметрии
по протоколу Орбита

ядро Орбита уже умеет принимать
и обрабатывать этот поток
```

Остальной функционал БСИ реализуется отдельно.

# Оставшиеся задачи разработки

Открытых вопросов нет.

Остались только работы:

```text
1. Обновить контактные точки:
   0 / 0,9 / 2,5 В.

2. Довести автоматическую процедуру ЯВП.

3. На живом стенде определить raw-признак обрыва.

4. Подключить до трёх автоматических повторов
   технических ошибок.

5. Удалить из текущего сценария обязательные:
   - insulation_evidence;
   - input_current_evidence;
   - sensor_supply_evidence;
   - reference_stream_evidence.

6. Пункт 1.1.4.9 закрывать автоматически
   данными ЯЛК + В7.

7. Добавить ЯВП в полный сценарий.

8. Обновить модель результатов:
   НОРМА /
   НЕ НОРМА /
   ОШИБКА СТЕНДА /
   общий итог НЕПОЛНАЯ ПРОВЕРКА.

9. Подключить режимы:
   acceptance /
   production.

10. Подключить RunStore к Registrar.

11. Обновить операторский и производственный UI.

12. Обновить протокол и производственную ведомость.
```

Все принятые решения считаются окончательными для текущей реализации и не должны повторно превращаться агентами в «открытые вопросы».
