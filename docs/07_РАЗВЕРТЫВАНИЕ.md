# Развёртывание на стенде Windows 11

Стендовая машина работает под Windows 11 и имеет адрес `192.168.0.50`.
Доставка файлов планируется по SSH/SCP. Предыдущие указания про Linux,
`/dev/tty*` и сборку Linux-пакета к этому стенду не относятся.

## Сначала собрать диагностику

Скопируйте на стенд только файл
`scripts/stand_full_diagnostics_win11.ps1`, откройте PowerShell от имени
администратора и выполните:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass `
  -File .\stand_full_diagnostics_win11.ps1 `
  -OutputDirectory C:\Users\Public\OrbitaDiag
```

Скрипт не меняет конфигурацию и не посылает команды приборам. Он:

- собирает версию Windows, архитектуру, диски и память;
- перечисляет сетевые интерфейсы, адреса, маршруты, ARP и занятые порты;
- проверяет ICMP-доступность Ethernet-адаптера `192.168.0.101`;
- пассивно слушает UDP `1001` и `1101`, не отправляя пакет адаптеру;
- перечисляет PnP/USB/COM-устройства и ошибки диспетчера устройств;
- собирает сведения о драйверах LCard/E20-10;
- ищет VISA runtime и связанные приборы;
- проверяет наличие OpenSSH Server и слушателя TCP/22;
- создаёт ZIP и отдельную контрольную сумму SHA-256.

Нужно вернуть два файла:

```text
C:\Users\Public\OrbitaDiag\orbita_stand_diag_<имя>_<время>.zip
C:\Users\Public\OrbitaDiag\orbita_stand_diag_<имя>_<время>.zip.sha256.txt
```

Отсутствие UDP-пакета во время пассивного ожидания не означает неисправность:
прошивка адаптера после включения находится в режиме `255` и начинает опрос
только после команды выбора режима.

## Включить SSH/SCP на Windows 11

Для текущей пары машин подготовлены:

- `scripts/enable_stand_remote_access_win11.ps1` — один раз запускается на
  стенде от имени администратора; устанавливает сервер, ключ и рабочие папки;
- `scripts/stand_remote.ps1` — запускается на машине разработчика для проверки
  связи, интерактивной оболочки, передачи файлов и удалённого запуска.

Правило брандмауэра разрешает TCP/22 только с текущего адреса машины
разработчика `192.168.0.171`. Закрытый ключ остаётся только в
`%USERPROFILE%\.ssh\id_ed25519_orbita_stand` и в репозиторий не добавляется.

На стенде нужно скопировать и один раз выполнить из PowerShell администратора:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass `
  -File .\enable_stand_remote_access_win11.ps1 `
  -UserName Azerty `
  -AllowedClientAddress 192.168.0.171
```

После этого на машине разработчика:

```powershell
.\scripts\stand_remote.ps1 -Action Status
.\scripts\stand_remote.ps1 -Action Shell
.\scripts\stand_remote.ps1 -Action V7Probe
```

Если учётная запись стенда называется не `Azerty`, в обеих командах нужно
передать её фактическое имя через `-UserName`.

Команды ниже изменяют конфигурацию Windows, поэтому выполняются на стенде
вручную от имени администратора только после проверки принятого порядка
администрирования:

```powershell
Get-WindowsCapability -Online -Name OpenSSH.Server*
Add-WindowsCapability -Online -Name OpenSSH.Server~~~~0.0.1.0
Start-Service sshd
Set-Service -Name sshd -StartupType Automatic
Get-NetFirewallRule -Name OpenSSH-Server-In-TCP -ErrorAction SilentlyContinue
```

Если стандартного правила нет, его можно создать:

```powershell
New-NetFirewallRule `
  -Name OpenSSH-Server-In-TCP `
  -DisplayName 'OpenSSH Server (sshd)' `
  -Enabled True -Direction Inbound -Protocol TCP -Action Allow -LocalPort 22
```

Проверка на стенде:

```powershell
Get-Service sshd
Get-NetTCPConnection -State Listen -LocalPort 22
```

Проверка с машины разработчика:

```powershell
Test-NetConnection 192.168.0.50 -Port 22
ssh <пользователь>@192.168.0.50
```

До этого TCP/22 на `192.168.0.50` отвечал отказом до авторизации. Это означает,
что SSH-сервер не слушал порт либо соединение отвергал локальный экран, а не
ошибку имени пользователя или пароля.

## Передача диагностического скрипта

После запуска SSH:

```powershell
scp .\scripts\stand_full_diagnostics_win11.ps1 `
  <пользователь>@192.168.0.50:stand_full_diagnostics_win11.ps1

ssh <пользователь>@192.168.0.50
powershell.exe -NoProfile -ExecutionPolicy Bypass `
  -File .\stand_full_diagnostics_win11.ps1 `
  -OutputDirectory C:\Users\Public\OrbitaDiag
```

Пароли и закрытые ключи в репозитории не хранятся.

## Будущий пакет OrbitaDesktop

Диагностика от 24.08.2026 показала, что Qt, CMake и Ninja на стенде не
установлены. Это целевая машина запуска, а не машина сборки. E20-10, LCard SDK
и NI-VISA Runtime на ней присутствуют. На машине разработчика формируется
Windows x64 release-каталог:

```text
OrbitaDesktop.exe
parameters.db
address\...
Lusbapi64.dll
Qt6*.dll и plugins\... (через windeployqt)
plugins\equipment\...
config\workstation.json
```

Каждый выпуск кладётся в отдельный каталог, например
`C:\Orbita\releases\<версия>`. Сначала выполняется запуск без оборудования,
потом проверка АЦП, телеметрии и каждого плагина. Предыдущий выпуск сохраняется
для отката.

IP `192.168.0.50` — адрес компьютера стенда. Его нельзя использовать вместо
адреса Ethernet-адаптера, ИСД или другого прибора.
