# Развёртывание на стенде Windows 11

Проводной интерфейс ПЭВМ `192.168.0.50` используется для оборудования.
Подтверждённый SSH/SCP-адрес этой же машины — `192.168.0.31`. Скрипт сверяет
имя `DESKTOP-5EO9J5A`; Qt и средства сборки на стенде не нужны, доставляется
готовый каталог выпуска.

## Диагностика до установки

На стенде из PowerShell администратора:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass `
  -File .\stand_full_diagnostics_win11.ps1 `
  -OutputDirectory C:\Users\Public\OrbitaDiag
```

Скрипт собирает Windows, сеть, маршруты, ARP, USB/PnP, COM, LCard/E20,
VISA, DLL и SSH, проверяет доступность известных адресов и пассивно слушает
UDP адаптера. Результат — ZIP и файл SHA-256.

После установки выпуска можно добавить безопасные пробы плагинов:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass `
  -File .\stand_full_diagnostics_win11.ps1 `
  -OutputDirectory C:\Users\Public\OrbitaDiag `
  -OrbitaDirectory C:\Orbita\releases\2026.08.26
```

`orbita_equipment_probe.exe` выполняет только идентификацию или чтение
состояния (`*IDN?`, `GETD` или эквивалент). Он не включает выходы и не меняет
маршруты.

## Доступ по SSH/SCP

Сначала запустите **на предполагаемой ПЭВМ стенда**, не через RDP и не на
соседнем приборе:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass `
  -File .\check_stand_access_win11.ps1
```

Скрипт выводит имя Windows, IPv4/MAC, состояние `sshd` и слушатель TCP/22.
Если в выводе нет ожидаемого IP, это не та машина, даже если она отвечает на
ping.

Один раз на стенде запустите от администратора:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass `
  -File .\scripts\enable_stand_remote_access_win11.ps1 `
  -UserName <пользователь-стенда> `
  -AllowedClientAddress <IP-компьютера-разработчика>
```

Проверка с компьютера разработчика:

```powershell
$standSshAddress = '<текущий SSH-адрес DESKTOP-5EO9J5A>'
Test-NetConnection $standSshAddress -Port 22
.\scripts\stand_remote.ps1 -StandAddress $standSshAddress -Action Status
.\scripts\stand_remote.ps1 -StandAddress $standSshAddress -Action Shell
```

Закрытые ключи и пароли в репозиторий не добавляются. Графическое приложение
нельзя штатно открыть в пользовательском сеансе из служебного SSH-сеанса;
удалённо выполняются доставка, диагностика и CLI-пробы, а `OrbitaDesktop.exe`
оператор запускает на рабочем столе стенда.

## Состав выпуска

```text
OrbitaDesktop.exe
orbita_equipment_probe.exe
parameters.db
address\...
catalog\catalog.yaml
profiles\stand_ktma.yaml
scenarios\ubsi_yalk_tu_5_6.yaml
scenarios\ubsi_ytp_tu_5_6.yaml
scenarios\ubsi_ytp_120_check.yaml
scenarios\ubsi_ulk_combined_check.yaml
plugins\orbita_plugin_*.dll
Qt6*.dll
platforms\qwindows.dll
Lusbapi64.dll
```

Сборка выполняется на машине разработчика:

```powershell
cmake -S . -B build -DBUILD_TESTING=ON -DCMAKE_BUILD_TYPE=Release
cmake --build build -j 4
ctest --test-dir build --output-on-failure
powershell.exe -NoProfile -ExecutionPolicy Bypass `
  -File .\scripts\package_stand_win11.ps1
```

Скрипт создаёт новый каталог выпуска, ZIP и `.sha256.txt` в
`build\deploy`. Он прекращает работу, если такое имя уже существует, и не
перезаписывает предыдущий выпуск.

Каждый выпуск копируется в новый каталог
`C:\Orbita\releases\<версия>`. Предыдущий каталог не перезаписывается — это
точка отката.

## Первый запуск

1. Оставьте `active_outputs_confirmed: false`.
2. Запустите диагностику и «Проверить оборудование» в приложении.
3. Сверьте `TODO_CONFIRM` в профиле со схемой А.1 и реальными каналами ИСД.
4. Выполните безопасные ручные проверки коммутации.
5. Только после подтверждения карты установите
   `active_outputs_confirmed: true`.
6. Сначала выполните диагностический неполный прогон, затем полный УБСИ.

Подключённый сейчас БСИ используется только для пассивной проверки цепочки
`E20-10 → liborbita → сценарный движок → интерфейс → отчёт`. Пункт
«Диагностика потока Орбита» всегда имеет итог `НЕПОЛНАЯ` и не является
испытанием БСИ по ТУ. Полный сценарий БСИ будет следующим этапом после УБСИ.

Адрес стендового интерфейса и текущий адрес SSH не взаимозаменяемы.
`stand_remote.ps1` больше не имеет адреса по умолчанию и проверяет, что
удалённая машина действительно называется `DESKTOP-5EO9J5A`.
