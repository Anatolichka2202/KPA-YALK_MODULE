Он не загружается целиком при старте агента.

# Канон и research — не одно и то же

Research отвечает:

> Откуда мы это узнали?

Канонический reference отвечает:

> Как система работает сейчас?

Поэтому после подтверждения факта:

```text
evidence
    ↓
research
    ↓
canonical docs
```

Например:

```text
захват KPA
    ↓
research/stand.md
    ↓
reference/protocols/rokt.md
```

# Приоритет доказательств для оборудования

Для фактического wire-протокола текущего стенда:

```text
1. живой захват рабочей референсной программы;
2. воспроизведение того же обмена нашим диагностическим инструментом;
3. повторяемый живой результат стенда;
4. архивный исходный код;
5. текущая реализация.
```

Текущий код не доказывает, что оборудование именно так работает.

# Чего здесь не должно быть

Не переносить сюда:

- дизайн-прототипы;
- продуктовые требования;
- копию ТУ;
- копию PROJECT_MEMORY;
- старую гипотезу только потому, что она когда-то обсуждалась;
- длинную хронику обычной разработки.

Если гипотеза опровергнута и не нужна для понимания доказательства,
в новую систему документации она не переносится.

# Evidence

`evidence/` может содержать исходные исследовательские артефакты:

- бинарники референсных программ;
- извлечённые строки;
- captures;
- сырые логи;
- фотографии;
- экспортированные результаты.

Наличие файла в `evidence/` не делает каждую строку внутри него истинной.

Истиной считается только явно сформулированный и подтверждённый вывод.
