# Референсные программы

Этот документ перечисляет программы, поведение которых используется как
инженерный референс при восстановлении фактической работы стенда.

Референсная программа не является источником требований ТУ.

---

# KPA_Rokot

Основной живой референс для адаптера УБСИ и последовательностей ЯЛК/ЯТП.

Артефакт:

```text
docs/research/evidence/reference-programs/kpa-rokot/KPA_Rokot.exe
```

SHA-256:

```text
ФАЙЛ НЕ НАЙДЕН
```

## Что KPA_Rokot подтверждает

В сочетании с живым сетевым захватом KPA_Rokot использовалась для
подтверждения:

- wire-команд ROKT;
- порядка запуска ЯЛК;
- порядка переключения ЯТП;
- размеров актуальных UDP-кадров;
- фактического HTTP-обмена с ИСД;
- последовательности отдельных физических действий;
- поведения реальной установки.

## Что из KPA_Rokot нельзя выводить автоматически

KPA_Rokot сама по себе не доказывает:

- требования ТУ;
- актуальный нормативный допуск;
- универсальность протокола для другой прошивки;
- правильность нашего сценария;
- правильность любой строки, найденной внутри бинарника;
- назначение неизвестного канала только по его имени.

Для wire-протокола доказательством является наблюдаемый живой обмен, а не
просто строка из executable.

# Извлечённые строки KPA_Rokot

В research/evidence сохранены поисковые выгрузки:

```text
strings-ascii.txt
strings-utf16.txt
```

Это только вспомогательный материал для поиска.

Строка внутри бинарника:

```text
!=
команда, подтверждённая живым стендом
```

Использовать найденную строку как рабочую команду можно только после
подтверждения захватом или воспроизведением.

# Как исследовать референс дальше

Для спорного действия:

```text
1. сформулировать один конкретный вопрос;
2. запустить рабочую KPA в чистом состоянии стенда;
3. снять соответствующий транспорт;
4. выделить минимальную последовательность команд;
5. повторить её отдельным безопасным probe;
6. сравнить результат;
7. записать подтверждённый вывод в research;
8. обновить canonical protocol-reference.
```

Не выполнять перебор неизвестных команд.
