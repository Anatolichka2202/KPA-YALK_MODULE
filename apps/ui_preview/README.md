# MilTechStation · UI Preview

**Статус:** изолированный прототип визуального интерфейса; никакой работы с физическим оборудованием. Не предназначен для эксплуатационных испытаний.

Этот проект создан для проверки концепции **гибридной оболочки** до переноса в основной desktop. Он не линкуется с orbita, StationSession, KTMA, сценарным движком и драйверами. Существующий MilTechStation.exe не изменён.

## Что реализовано

- Полная MilTechStation / КТМА: **Обзор, Рабочая область, Оборудование, Сценарии, Результаты**.
- Полная MilTechStation / reference_device: те же структурные экраны, другой состав поставки без KTMA-специфичных действий.
- Отдельная TU/УБСИ UX-концепция: **Подготовка, Испытание, Результат**.
- Тёмная тема Industrial Precision из `theme.qss`.
- Две инженерные dock-панели, которые можно перемещать и собирать во вкладки.
- Сохранение компоновки для каждой полной поставки отдельно через QSettings и QMainWindow::saveState/restoreState.
- Клавиатурная навигация Alt+1…5; интерфейс без обязательного разрешения 1920×1080.
- Явное обозначение отсутствия runtime, данных, измерений и готовности.

Все «операции» и аппаратно-зависимые действия в прототипе отсутствуют или отключены.

## Как запустить

Требования: Qt **6.8+** с модулем Widgets, компилятор C++17, CMake 3.20+.

Windows / Qt MinGW (пример; подставьте собственный путь к Qt):

```powershell
cmake -S apps/ui_preview -B build/ui-preview -G Ninja -DCMAKE_PREFIX_PATH="C:/Qt/6.8.0/mingw_64"
cmake --build build/ui-preview
.\build\ui-preview\MilTechStationUiPreview.exe
```

Устанавливать весь проект и собирать MilTechStation.exe не требуется. Это намеренно **отдельный CMake-проект**. Если используется Qt Creator, откройте `apps/ui_preview/CMakeLists.txt` и выберите существующий desktop kit.

## Что попробовать вручную

1. Переключить «Полная · КТМА» → «Полная · эталонный имитатор»; проверить содержание карточек и списка оборудования.
2. Перейти в «Рабочая область»; перетащить «Параметры» вправо/вниз, «Журнал событий» — во вкладку или отдельное окно.
3. Перейти в другой раздел и обратно; затем сменить поставку и проверить изоляцию сохранённой компоновки.
4. Переключить «ТУ · УБСИ»: должна появиться только последовательность из трёх шагов без инженерных доков.
5. Убедиться, что «Подготовить проверку» и «Открыть протокол» недоступны, а фактические измерения не подделаны.
6. Проверить читаемость при 1366×768, 1600×900, 1920×1080, масштабировании 125%/150% и keyboard focus.
7. Проверить закрытие/возврат док-панелей и поведение при смене мониторов — это зона известного UI-долга.

## Архитектурная оговорка

`main.cpp` пока специально объединяет экранные компоненты в одном файле, чтобы максимально изолировать концепцию от производственного кода. **Это не окончательная структура UI-модулей.** При утверждении макета её нужно разнести на Shell, Theme, Components, Screens, Presentation models, внести тесты и подключить к существующим ProjectDefinition/StationSession только через адаптер представления.

Не подключать прототип к железу, не добавлять текущие TU workflow в этот executable. Следующий шаг — UI QA и компонентный каталог; затем — отдельная реализация настоящего TU executable и подключение к штатной системе только после утверждения контрактов.

## Статус проверок

Код сохранён в репозиторий и прошёл статическую проверку структуры. Сборка, запуск Qt GUI на Windows и визуальная проверка **не выполнены** в среде создания: здесь отсутствует Qt 6 SDK. Это необходимо проверить в целевом Qt 6.8 kit.
