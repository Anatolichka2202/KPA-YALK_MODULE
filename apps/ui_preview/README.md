# MilTechStation · UI Preview 0.4

**Статус:** автономный Qt Widgets интерфейсный прототип. Не предназначен для стендовых испытаний.

Прототип показывает гибридную компоновку полной MilTechStation, вариативность интерфейса по поставке и отдельный операторский поток ТУ. Он **не** линкуется с StationSession, Orbita, драйверами, БД стенда или исполнителем методик. Ни одной команды оборудованию здесь нет.

## Что можно посмотреть

**Полная программа / КТМА или reference_device**

- **Редактор HMI-представлений:** отдельный экран «HMI-представления», полотно 960×540, шесть типов элементов (число, состояние, шкала, мини-график, подпись, макет команды), инспектор свойств/привязок, перетаскивание по сетке, импорт/экспорт JSON.
- **HMI в инженерной рабочей области:** тот же документ отображается в режиме просмотра; изменения в редакторе видны без перезапуска. При отсутствии данных отображаются пустые состояния; синтетика доступна отдельно и всегда маркирована.
- **Ограничение:** все ключи `ui.demo.*` демонстрационные; команда в HMI заблокирована. Реального data binding, управления устройствами и публикации HMI в ТУ-сборку пока нет.

- **Сборная структура HMI:** состав экранов загружается из проверяемых JSON UI-манифестов (`manifests/ktma.json`, `reference.json`, `tu_ubsi.json`).
- Два новых служебных раздела: **Конфигуратор** (черновик ограниченной ТУ-сборки) и **Администрирование** (станция, оборудование, поставки, доступ и аудит).
- Конфигуратор меняет параметры **только локального UI-черновика** и обновляет JSON-предпросмотр; сборка EXE намеренно отключена, потому что ядро конфигуратора пока не подключено.
- Административные действия выключены; реальные профили, права пользователей и журналы из станции не считываются.

- Обзор, рабочая область, оборудование, сценарии, результаты.
- Инженерная рабочая область с локальным QMainWindow и док-панелями внутри неё.
- Таблица параметров на QAbstractTableModel / QTableView + QSortFilterProxyModel: поиск, значения, единицы, источник, качество.
- Демонстрационный график через QPainter: тренд или счётчик 0–1023 («пила»). Только **математические синтетические значения**, без RS-485 и чтения Орбиты.
- Галочка «Показывать синтетические данные», демонстрирующая состояние «нет измерений».
- Логическая схема представления, НЕ физическая схема проводки или readback коммутации.
- Браузер оборудования с карточками и исходным состоянием «Не опрошен».
- Отдельный журнал событий интерфейса (не записи EvidenceEvent стенда).
- Сохранение компоновки через QSettings отдельно для КТМА и reference_device, кнопка возврата исходного layout.

**ТУ / УБСИ**

- Подготовка → Испытание → Результат.
- Фиксированные операторские экраны без инженерных док-панелей и инструментов изменения методики.
- Реальный запуск, подготовка оборудования и экспорт отчётов намеренно недоступны.
- Это **экранная симуляция самостоятельной ТУ-сборки**, пока не отдельный production executable.

Главная метка «UI PREVIEW · БЕЗ ОБОРУДОВАНИЯ» остаётся видимой во всех режимах.

## Добавление UI-поставки

Создайте JSON в `manifests/` по примеру существующего файла и добавьте его путь в `resources.qrc`. После пересборки селектор обнаружит ресурс автоматически; менять C++ не требуется. `id` должен быть уникальным и содержать только латинские буквы, цифры, `_` или `-`. Поля `title`, `kind`, `screens`, `workspaceComponents` и `demo` задают название, тип, состав экранов и демонстрационные подписи. В `demo.sample` выберите существующий набор синтетических примеров `ktma` или `reference`; это не измерения и не состав реального стенда. Поддерживаются только уже реализованные ID экранов и компонентов. Для `kind: "tu"` разрешены только три операторских экрана и запрещены инженерные компоненты. Ошибочные манифесты и повторяющиеся ID пропускаются с диагностикой в журнале Qt.

## Сборка

Нужны Qt 6.8+ Widgets, C++17, CMake 3.20+, Ninja и соответствующий компилятор.

Windows / Qt 6.8 MinGW:

```powershell
cmake -S apps/ui_preview -B build/ui-preview -G Ninja -DCMAKE_PREFIX_PATH="C:/Qt/6.8.0/mingw_64"
cmake --build build/ui-preview
.\build\ui-preview\MilTechStationUiPreview.exe
```

Откройте `apps/ui_preview/CMakeLists.txt` в Qt Creator, если хотите использовать уже настроенный kit.

### UI-smoke без оборудования

```powershell
$env:QT_QPA_PLATFORM = "offscreen"
.\build\ui-preview\MilTechStationUiPreview.exe --ui-smoke
```

Проверяются размеры окна 800×600, 1024×768, 1366×768 и 1600×900, прокрутка навигации, перестроение карточек и оборудования, загрузка четвёртого тестового манифеста, переходы по его экранам, обработка ошибок и число экранов каждой поставки, отсутствие инженерных панелей в ТУ, переключение графика/синтетики, поиск параметра, количество демонстрационных компонентов и журнал UI.

### Снимки реального Qt-рендера

```powershell
$env:QT_QPA_PLATFORM = "offscreen"
.\build\ui-preview\MilTechStationUiPreview.exe --ui-snapshot-dir build/ui-preview/screenshots
```

Формируются PNG всех экранов каждого варианта при 800×600, 1024×768, 1366×768 и 1600×900 — **76 снимков** при 8 + 8 + 3 разделах. `ui-preview.yml` публикует их как GitHub Actions artifact `miltech-ui-preview-screenshots` для визуальной проверки. Снимки не являются подтверждением корректности текста/компоновки: визуальное QA остаётся отдельным действием.

Откройте [UI Preview workflow](../../.github/workflows/ui-preview.yml) для результатов CI.

## UX-проверка вручную

1. Переключить КТМА → reference → ТУ; убедиться, что нет действий КТМА в reference и инженерных доков в ТУ.
2. Войти в «Рабочая область», поменять местами «Параметры» и «Журнал», перейти в другой раздел и обратно.
3. Нажать «Исходная компоновка». Повторить после переключения поставки.
4. Набрать в поиске `Параметр`, `DEMO.04`, затем несуществующий код; проверить пустое состояние.
5. Переключить демонстрационный тренд на пилу и снять галочку синтетических значений; убедиться, что фальшивый сигнал исчез.
6. Проверить 1366×768, 1600×900, 1920×1080, масштабирование 125%/150%, клавиатуру и контраст.
7. Вынести док на второй экран, затем отключить монитор и восстановить layout. Это открытый риск, автоматический smoke его не покрывает.

## Ограничения и следующий шаг

Сейчас code-behind оболочки остаётся в `main.cpp`, а переиспользуемые компоненты вынесены в `components.h/.cpp`. Текущая навигация теперь формируется по screen IDs из JSON-манифестов. Следующие UI-only изменения: полноценный registry компонентных фабрик, модели состояний и источников, гибкая система пресетов, проверка доступности и многомониторная QA. Ни один этап не требует менять существующие методики/протоколы.

Факт успешной CI-сборки подтверждает компиляцию/базовые взаимодействия, но **не** заменяет пользовательские UX-проверки и испытания физического стенда.
