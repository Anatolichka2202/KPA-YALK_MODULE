# УБСИ · поправка к backend проверок от 2026-09-08

Статус: **каноническая поправка текущей реализации**.

Эта запись фиксирует предметные решения, подтверждённые владельцем методики 2026-09-08. До выпуска формально исправленной редакции ТУ она имеет приоритет для программной реализации над противоречащими местами старого проекта ТУ, старых сценариев и прежних design/backend notes.

## 1. 1.1.4.1 · пьезоэлектрические каналы

В загруженном проекте `УБСИ_ТУ_Проект.docx` осталось старое значение «не менее 16 каналов».

Для текущего УБСИ это исправляется на:

```text
ЯВП-8 = 8 пьезоэлектрических каналов
```

Backend, UI, отчёт и тесты не должны создавать 16 каналов ЯВП.

## 2. 1.1.4.2 · питание датчиков / ток

Схема автоматической проверки поканального тока и нагрузок 350/450 мА была предложена и отвергнута.

В текущем стенде **нет технического измерительного тракта поканального тока**. Поканальный ток не является телеметрией ЯЛК и не измеряется В7 или иной текущей аппаратурой КТМА.

Следствия для текущего ПО:

- не выполнять автоматические воздействия `sensor_load_350ma` / `sensor_load_450ma`;
- не формировать поканальный ток из данных ЯЛК;
- не подменять поканальный ток общим током блока;
- не требовать внешний протокол/evidence для закрытия текущего автоматизированного run;
- при контроле цепи 6,2 В не выполнять отдельный нагрузочный тест 350/450 мА; остальные функции блока должны оставаться работоспособными;
- в будущем допустима ручная форма для ввода/фиксации значения, но до формального изменения методики это только ручная запись и не автоматический нормативный verdict.

Ожидается, что руководство уберёт этот спорный поканальный контроль из следующей редакции ТУ. **До появления официальной редакции ПО не должно утверждать, что формальный текст ТУ уже изменён.**

## 4. 1.1.4.5 · ток потребления УБСИ

Проверяется **общий ток потребления всего УБСИ**, измеряемый источником питания стенда.

Не существует поканального измерения тока.

Рабочий диапазон из текущего проекта ТУ:

```text
24...35 В
Iобщ <= 0,4 А
```

Критерий `0,4 А` относится к измеренному общему потреблению изделия. Аппаратная уставка ограничения тока источника питания — отдельная защитная величина и не должна использоваться как замена измерительного критерия. Для стенда допустима защитная уставка, например `0,6 А`, при отдельной проверке измеренного `Iобщ <= 0,4 А`.

## 6. Входной ток <= 2 мкА из 1.1.4.14

Текущая аппаратура КТМА не позволяет достоверно измерить входной ток отдельного канала <= 2 мкА.

Поэтому:

- автоматического измерения нет;
- общий ток УБСИ с АКИП не является заменой этого измерения;
- данные ЯЛК не являются источником такого тока;
- отсутствие измерения не превращается в `НЕ НОРМА` изделия;
- возможно дальнейшее ручное поле как запись оператора, но не автоматический verdict без отдельной утверждённой методики.

Ожидаемое исключение этого требования руководством из будущей редакции ТУ пока не считается свершившимся фактом.

## 7. ЯВП-8 · источник данных

Внешний результат ЯВП читается **через ЯЛК**, не через `orbita.parameter_source` / E20.

Каталог использует `ulk_address` как 1-based адрес и хранит `word_index = ulk_address - 1`. Поэтому восемь каналов фиксируются однозначно:

| ЯВП | `ulk_address` ЯЛК | `word_index` |
|---:|---:|---:|
| 1 | 89 | 88 |
| 2 | 90 | 89 |
| 3 | 91 | 90 |
| 4 | 92 | 91 |
| 5 | 93 | 92 |
| 6 | 94 | 93 |
| 7 | 95 | 94 |
| 8 | 96 | 95 |

Иными словами, операторская формулировка «88–96, восемь адресов» в backend нормализована как **слова 88–95 / логические адреса ЯЛК 89–96**. Девятого канала нет.

## 8. ЯВП-8 · текущий backend contract

Физическая цепь:

```text
Rigol DG-1022Z -> C=1000 пФ -> вход ЯВП -> ЯВП -> ЯЛК 89...96 -> UDP
```

Коэффициенты:

```text
0.25 / 0.5 / 1 / 2 / 4 / 8 / 32 мВ/пКл
```

Амплитуда генератора по коэффициенту:

```text
0.25 -> 8 В
0.5  -> 4 В
1    -> 2 В
>1   -> 1 В
```

Контрольные частоты текущей принятой методики:

```text
0.15 / 20 / 250 / 500 / 1800 / 2000 / 4000 Гц
```

На каждой точке использовать не менее 16 **свежих** UDP-кадров после переключения воздействия.

Расчёты:

```text
Q[pC] = C[pF] * Uin[V]
Kmeas[mV/pC] = 1000 * Uout[V] / Q[pC]
dK[%] = (Kmeas - Kset) / Kset * 100
критерий быстроменяющегося канала: |dK| <= 7 %

AFC[%] = (A(f) / Aref - 1) * 100
Attenuation[dB] = 20 * log10(Aref / A(f))
```

Точки АЧХ рабочего диапазона из текущего проекта ТУ используют зоны `±10 / ±5 / ±10 %`; на `2Fв` и выше в проекте ТУ записано затухание «не менее 20–30 дБ». Конкретная опорная частота `Aref`, окончательная числовая граница затухания из диапазона `20–30 дБ`, физическая карта ИСД `yvp_input/yvp_gain` и подтверждение того, как именно `Uout` извлекается из живых слов 89–96, являются **commissioning/configuration tasks**, а не новыми продуктовыми вопросами.

До их подтверждения активный YVP callback обязан завершаться `INCOMPLETE` **до включения Rigol**.
