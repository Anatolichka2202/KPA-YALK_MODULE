# КТМА / УБСИ — поправка production stage UI

Статус: каноническая поправка к `_plans/ubsi-next-minimal-delivery.md`.
При конфликте по отображению и порядку производственных этапов эта поправка имеет приоритет.

## 1. Production stage — это metadata изделия/run

В текущем производственном контуре используются ровно семь этапов в следующем пользовательском порядке:

1. `Первичное`
2. `Климат НУ`
3. `Климат +`
4. `Климат −`
5. `Заливка · климат НУ`
6. `Заливка · климат +`
7. `Заливка · климат −`

Стабильные внутренние коды сохраняются:

- `INITIAL`
- `CLIMATE_NORMAL`
- `CLIMATE_HIGH`
- `CLIMATE_LOW`
- `POTTED_CLIMATE_NORMAL`
- `POTTED_CLIMATE_HIGH`
- `POTTED_CLIMATE_LOW`

Legacy-строки старой четырёхэтапной модели остаются читаемыми только для истории.

## 2. Этапы НЕ являются шагами измерительной процедуры

Запрещён UI вида:

```text
01 Назначение
02 Готовность
03 Калибровка
04 Каналы ЯЛК
05 ЯТП 0 Ом
06 ЯТП 120 Ом
07 ЯТП 240 Ом
08 Итог
```

Это внутренний ход конкретного сценария, а не lifecycle изделия.

Также не показывать оператору производственный run как мастер/stepper `1 → 2 → 3 → ...` по внутренним измерительным операциям.

## 3. Правильная модель

Перед запуском Production оператор выбирает независимо:

```text
Изделие
Этап производства
Проверку / пакет
```

Например:

```text
Изделие: УБСИ-468157-009
Этап: Климат НУ
Проверка: Полная проверка УБСИ
```

После запуска процедура выполняется так же, как существующие текущие испытания: ScenarioEngine последовательно выполняет необходимые действия, а UI показывает текущую операцию, прогресс, результаты каналов и требуемые ручные действия.

Внутренние операции (`калибровка`, `точка 120 Ом`, `cleanup` и т.п.) не становятся production stages.

## 4. TU / ПСИ

Приёмо-сдаточный run вообще не имеет production stage и не двигает production lifecycle.

ПСИ выполняет полный нормативный маршрут текущей методики. UI не должен превращать этот маршрут в редактируемую лестницу из восьми экранов. Обычный оператор видит:

- выполняемую сейчас проверку;
- общий прогресс;
- ручное действие, когда оно действительно требуется;
- результат;
- Safe Stop.

## 5. UI-инвариант

На экране активного Production run одновременно должны быть различимы две вещи:

```text
ЭТАП ИЗДЕЛИЯ: Климат НУ
ТЕКУЩАЯ ОПЕРАЦИЯ: ЯЛК · канал 47 / 80
```

Они не взаимозаменяемы.

## 6. Порядок отображения

Во всех новых UI списках этапов использовать пользовательский порядок:

```text
Первичное
Климат НУ
Климат +
Климат −
Заливка · климат НУ
Заливка · климат +
Заливка · климат −
```

Не возвращать `Первичная`, если речь о подписи производственного этапа в операторском UI.
