# AMENDMENT — ЯЛК: обязательная методика проверки перегрузки ±12 В

Статус: каноническое уточнение текущей SUPER SPEC  
Область: УБСИ / ЯЛК / проверка устойчивости остальных каналов при перегрузке входа ±12 В  
Приоритет: этот документ имеет приоритет над прежней упрощённой формулировкой проверки `yalk_overload` и над старым критерием `±0,5 % FS` для данной процедуры.

## 1. Смысл проверки

Проверяется не просто факт подачи `+12 В` и `−12 В` на входы ЯЛК.

Проверяется, что при перегрузке одного физического входа показания остальных каналов ЯЛК не изменяются более чем на `±2` кодовые единицы относительно значений, сохранённых непосредственно перед проверкой перегрузки.

Критерий для незатронутого канала `j`:

```text
Δ[j] = measured_under_overload[j] - baseline[j]

НОРМА, если:
-2 <= Δ[j] <= +2
```

Эквивалентно:

```text
abs(Δ[j]) <= 2
```

Это не критерий `±0,5 % FS` и не критерий в вольтах.

## 2. Количество физических каналов

Проверяется последовательность физических каналов ЯЛК:

```text
1 ... 88
```

Для overload-route использовать 88 физических каналов.

Не сокращать процедуру до 80 каналов из-за того, что другие процедуры ЯЛК могут работать с другим числом измерительных адресов.

## 3. Фаза baseline

Перед первым воздействием `+12 В` необходимо выполнить исходную последовательность воздействий («лесенку») по всем 88 каналам ЯЛК и сохранить полученные значения:

```text
baseline[1]
baseline[2]
...
baseline[88]
```

Baseline должен быть получен в текущем запуске непосредственно перед overload-проверкой.

Запрещено вместо baseline использовать:

- номинал;
- значение из БД;
- результат предыдущего запуска;
- расчётное значение;
- допуск `±0,5 % FS`.

### Точная форма исходной «лесенки»

Конкретные точки и команды исходной «лесенки» должны быть восстановлены из подтверждённого источника:

1. рабочая КРА/КПА;
2. `report.log` / capture;
3. существующая подтверждённая реализация стенда;
4. подтверждённые команды ИСД.

Произвольные точки не подставлять.

Если точную «лесенку» по имеющимся источникам подтвердить невозможно: **Я не могу это подтвердить.** Это commissioning-задача, а не новый продуктовый вопрос.

## 4. Обязательный переход в безопасное состояние после baseline

После получения и сохранения baseline обязательно:

```text
1. СБРОС ИСД
2. ОТКЛЮЧИТЬ ВЫХОД ЦАП
3. ВЫЖДАТЬ ПАУЗУ
4. только затем разрешается подключать +12 В
```

Нельзя оставлять активным прежнее воздействие ЦАП.

Нельзя переходить:

```text
baseline -> сразу +12 В
```

без сброса ИСД, отключения ЦАП и выдержки.

## 5. Положительная половина: +12 В

Перегрузка выполняется строго последовательно:

```text
канал 1
канал 2
канал 3
...
канал 88
```

Для каждого `stressed_channel = i` алгоритм одинаков.

### 5.1. Перед воздействием

Убедиться, что предыдущая операция полностью снята:

```text
ИСД сброшен
ЦАП отключён
выдержана пауза
```

### 5.2. Воздействие

Подключить `+12 В` на шину входа физического канала `i`.

После установленной выдержки считать актуальные значения ЯЛК.

### 5.3. Сравнение

Для каждого наблюдаемого канала:

```text
j = 1 ... 88
j != i
```

рассчитать:

```text
Δ[j] = current[j] - baseline[j]
```

Критерий:

```text
abs(Δ[j]) <= 2
```

Перегружаемый канал `i` в критерий устойчивости **остальных** каналов не входит.

### 5.4. Обязательный cleanup после каждого канала

После проверки канала `i` обязательно:

```text
1. снять +12 В;
2. выполнить СБРОС ИСД;
3. отключить выход ЦАП;
4. выдержать паузу;
5. убедиться в безопасном состоянии;
6. только затем переходить к каналу i+1.
```

Запрещён алгоритм:

```text
+12 ch1 -> +12 ch2 -> +12 ch3
```

без полного промежуточного сброса.

Правильная форма:

```text
+12 ch1
-> RESET ИСД
-> DAC OFF
-> WAIT

+12 ch2
-> RESET ИСД
-> DAC OFF
-> WAIT

...

+12 ch88
-> RESET ИСД
-> DAC OFF
-> WAIT
```

## 6. Переход между полярностями

После завершения `+12 В` на канале 88 обязательно:

```text
снять +12 В
-> RESET ИСД
-> DAC OFF
-> WAIT
```

Только затем начинать отрицательную половину.

## 7. Отрицательная половина: −12 В

Полностью повторить ту же последовательность для `−12 В`:

```text
канал 1
канал 2
...
канал 88
```

После каждого отдельного канала:

```text
−12 chN
-> снять воздействие
-> RESET ИСД
-> DAC OFF
-> WAIT
```

Критерий тот же:

```text
abs(measured[j] - baseline[j]) <= 2
```

для каждого незатронутого канала `j != stressed_channel`.

## 8. Псевдокод

```text
baseline = acquire_baseline_staircase(channels=1..88)

ISD_RESET
DAC_OFF
WAIT

for polarity in [+12V, -12V]:

    for stressed_channel in 1..88:

        assert_safe_state()

        connect_overload(stressed_channel, polarity)
        WAIT_OVERLOAD_SETTLE

        current = read_yalk_channels(1..88)

        for observed_channel in 1..88:

            if observed_channel == stressed_channel:
                continue

            delta =
                current[observed_channel]
                - baseline[observed_channel]

            result =
                NORM
                if abs(delta) <= 2
                else NOT_NORM

            save(
                polarity,
                stressed_channel,
                observed_channel,
                baseline[observed_channel],
                current[observed_channel],
                delta,
                result
            )

        disconnect_overload()

        ISD_RESET
        DAC_OFF
        WAIT

ISD_RESET
DAC_OFF
WAIT
```

## 9. Что сохранять

Для каждой комбинации воздействия сохранять минимум:

```text
полярность перегрузки
перегружаемый канал
наблюдаемый канал
baseline code
code при перегрузке
delta
lower limit = -2
upper limit = +2
verdict
```

Не сохранять только общий PASS/FAIL.

Это необходимо, чтобы по результату было видно, какой именно наблюдаемый канал изменился при перегрузке какого физического входа.

## 10. Verdict

Для конкретного наблюдаемого канала:

```text
abs(delta) <= 2
-> НОРМА
```

```text
abs(delta) > 2
-> НЕ НОРМА
```

Если воздействие нельзя корректно выполнить либо нельзя получить достоверные данные:

```text
ОШИБКА СТЕНДА
```

Не превращать техническую ошибку стенда в `НЕ НОРМА` изделия.

## 11. Safe cleanup — обязательный инвариант

При любом:

```text
Stop
exception
timeout
ОШИБКА СТЕНДА
```

процедура обязана попытаться выполнить:

```text
снять ±12 В
RESET ИСД
DAC OFF
вернуть коммутацию в safe state
```

Cleanup должен быть гарантирован также при исключении внутри цикла по каналам.

## 12. Изменение относительно текущего YAML

В текущей конфигурации `yalk_overload` уже присутствуют правильные структурные признаки:

```text
physical_channel_count: 88
observed_address_count: 88
positive_overload_route: yalk_overload_positive
negative_overload_route: yalk_overload_negative
```

Их сохранить.

Старый критерий:

```text
tolerance_percent_fs: 0.5
```

для этой проверки больше не является критерием устойчивости остальных каналов.

Целевой параметр сценария должен быть однозначным, например:

```text
maximum_code_delta: 2
```

или эквивалентным по смыслу.

Также процедура должна явно обеспечивать между каждым воздействием:

```text
RESET ИСД
DAC OFF
WAIT
```

Нельзя полагаться на неявное предыдущее состояние оборудования.

## 13. Неподтверждённые технические величины

На момент фиксации этого amendment не подтверждены документально:

1. точные значения и последовательность исходной «лесенки»;
2. точная длительность паузы после `RESET ИСД + DAC OFF`.

Эти значения необходимо взять из подтверждённого стендового источника. Их запрещено угадывать.
