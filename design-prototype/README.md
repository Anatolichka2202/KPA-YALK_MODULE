# Дизайн-прототип КТМА / УБСИ

Интерактивный UX/UI-прототип промышленного desktop/HMI-приложения. Он демонстрирует пользовательские сценарии, состояния, динамические DEMO-данные и отчётность; измерительные algorithms, wire protocol, backend и production Qt/C++ этим прототипом не изменяются.

## Активный entry point

Сейчас `src/main.jsx` запускает:

```text
src/ubsi/UbsiSupplyApp.jsx
```

Это предметный прототип текущей поставки УБСИ:

```text
КТМА / УБСИ
├── ПРОИЗВОДСТВО
├── ПРИЁМО-СДАТОЧНАЯ ПРОВЕРКА ПО ТУ
├── АДМИНИСТРИРОВАНИЕ
└── F12 · инженерный слой
```

Общая Station/Product Launcher-концепция **не удалена**. Старые `AppV1.jsx`, `src/v1/` и `station-v1*.css` остаются в репозитории как следующий более широкий архитектурный слой, но не являются активным entry текущего предметного прохода.

## Запуск

Из `design-prototype/`:

```bash
npm install
npm run dev
```

Production-style browser build:

```bash
npm run build
npm run preview
```

## Что можно пройти кликами

### Производство

- найти УБСИ;
- зарегистрировать новый блок;
- выбрать production stage;
- открыть `УБСИ / ЯВП / ПО ЯЧЕЙКАМ`;
- запустить production run;
- видеть 80 подтверждённых рабочих адресов ЯЛК в динамике;
- выбирать адрес кликом по столбцу;
- видеть фактическое значение, отклонение, selected trace, фоновую динамику и потребление;
- открыть отдельное представление overload по 88 физическим каналам;
- воспроизвести `НЕ НОРМА`, `STALE`, `ОШИБКА СТЕНДА`, overload fail;
- выполнить ручное действие Р4831;
- Safe Stop;
- открыть производственную ведомость и сохранённое визуальное представление динамики.

### ТУ

- ввести номер УБСИ;
- автоматическая подготовка стенда;
- единый TU run без production stage;
- Р4831;
- ошибка стенда;
- Safe Stop;
- короткий чёрно-белый итоговый протокол.

### Администрирование

- изделия;
- текущий состав;
- SN ячеек;
- замены ЯЛК / ЯТП / ЯВП / ЯП-П;
- предложение обязательной связанной повторной проверки;
- entry-точки истории production/TU runs и состояния стенда.

## DEMO telemetry

`src/ubsi/demoTelemetry.js` генерирует детерминированный синтетический поток только для UX:

- 80 рабочих адресов ЯЛК;
- actual V;
- deviation % FS;
- raw/code placeholders;
- selected-channel trace;
- фоновую историю всех адресов;
- ток и напряжение;
- отдельную модель 88 физических каналов overload.

Это **не данные реального стенда**.

Числа из требований используются только там, где они подтверждены текущей методикой/каталогом. Подробная карта источников: `docs/specs/ubsi-supply-prototype-v1.md`.

## ЯЛК — модель UI

Обычные analog/contact procedures используют 80 подтверждённых рабочих УЛК-адресов:

```text
1–28, 32–43, 45–70, 74–87
```

Калибровка:

```text
97 / 99
0...6,2 В
```

Аналоговые точки:

```text
0 / 3,1 / 6,2 В
```

Контактные точки:

```text
0,0 В -> 0
0,9 В -> 0
2,5 В -> 1
```

Overload — отдельная модель:

```text
88 физических каналов
+12 / -12 В
|Δcode| <= 2 для остальных каналов
```

Не выводить 96 одинаковых столбцов только из названия `ЯЛК-96`.

## ЯВП

UI использует подтверждённые частоты:

```text
0,15 / 20 / 250 / 500 / 1800 / 2000 / 4000 Гц
```

Текущий catalog ещё не подтверждает live-binding ЯВП к потоку адаптера. Поэтому числовое ЯВП-представление в browser-prototype остаётся `DEMO / commissioning` и не формирует выдуманный нормативный verdict.

## Источник правды

1. Актуальная редакция ТУ УБСИ.
2. `_plans/ubsi-next-minimal-delivery.md` и канонические amendments.
3. Подтверждённый живой стенд / capture / журнал.
4. Текущая production-реализация и catalog.
5. UX-прототип как interaction contract, но не как источник измерительной методики.

## Целевой viewport

Основной: **1920×1080**.

Дополнительно предусмотрена адаптация под более узкие окна, но фактический browser/screenshot QA считается пройденным только после реального запуска.
