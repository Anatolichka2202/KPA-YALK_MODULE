# Дизайн-прототип «МилТех Станция / КТМА»

Единая рабочая папка UX/UI-концепции промышленного desktop/HMI-приложения. Прототип в `src/` демонстрирует компоновку окон, состояния и взаимодействия; он не изменяет алгоритмы `orbita/`, backend, C++ или производственный Qt-код.

## Структура

- `src/AppV1.jsx` — текущая навигационная модель Station/КТМА.
- `src/v1/` — общие Station-компоненты и экраны рабочего среза v1.
- `src/station-v1.css` — текущая semantic visual system.
- `src/App.jsx`, `src/styles.css` — предыдущий прототип, сохранён для сравнения и истории; не является активным entry point ветки v1.
- `public/assets/brand/current/` — текущие исходники знака и вордмарка.
- `references/approved/` — принятые визуальные направления.
- `references/rejected/` — отклонённые концепции, сохранённые для истории.
- `docs/research/` — результаты исследований и вопросников; могут отражать исторические решения.
- `docs/specs/station-shell-v1.md` — текущая IA и state model.
- `docs/specs/design-system-v1.md` — общий design-system contract.
- `docs/specs/designer-deliverables-v1.md` — обязанности дизайнера, готовность и backlog.
- `docs/specs/final-tu-protocol.md` — ограничения и структура итогового протокола.
- `docs/qa/` — результаты проверок; не обновлять статусом `passed` без фактического прогона.
- `archive/legacy-prototype-2026-09-05/` — прежний статический HTML-прототип.

## Источник правды

1. ТУ и утверждённая методика.
2. Подтверждённые протоколы стенда и техническая проектная память.
3. Актуальная UX/design SUPER SPEC проекта.
4. Подтверждённые решения производства/руководства.
5. Канонические документы `docs/specs/` текущей ветки.
6. React-прототип — визуальная спецификация и демонстратор взаимодействий, а не реализация измерительных алгоритмов.

При конфликте исторического research-документа и текущей канонической UX-спецификации решение фиксируется в `docs/specs/` без переписывания истории исследования задним числом.

## Принятое направление v1

- **«МилТех Станция»** — общий shell для продуктов, активных сеансов и общих ресурсов.
- **КТМА** — продукт/надстройка внутри Станции.
- Верхний уровень КТМА содержит три рабочие задачи: **Производство**, **Приёмо-сдаточная проверка по ТУ**, **Администрирование**.
- Эти рабочие задачи не являются пользовательскими ролями и не переключаются F12.
- **F12 открывает инженерный режим**, сохраняя текущую рабочую задачу и активный сеанс.
- Permission level проверяется отдельно от F12 и отдельно от рабочей задачи.
- Промышленная синевато-чёрная тема, высокая плотность данных, минимум управляющих кнопок.
- Никаких burger-меню, браузерных вкладок и декоративных SaaS-карточек.
- Safe Stop занимает постоянную позицию в command bar активного сеанса.
- Ручные физические операции используют общий паттерн Manual Action.
- Канальный производственный HMI показывает все каналы одновременно; selected-channel trend и consumption trend являются вторичными графиками.
- Прототипные числовые значения маркируются как demo-data, если они не подтверждены нормативным или стендовым источником.
