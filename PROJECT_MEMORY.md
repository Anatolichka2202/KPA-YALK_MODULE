# 4. Подтверждённый тракт ЯЛК

## Адаптер

Текущий живой тракт:

```text
Ethernet/RS-485 adapter
192.168.0.115
UDP 1113
```

Подтверждённая команда запуска ЯЛК содержит:

```text
ROKT 0A 00 00 01 00
```

Перед запуском используется подтверждённая адресация ROKT.

После запуска ожидается свежий UDP-кадр:

```text
длина: 204 байта
header: 02 00 2B 00
структура:
    4-byte header
    +
    100 x uint16 little-endian
```

Декодирование слова:

```text
analog = raw & 0x03FF
signal = (raw & 0x0400) != 0
```

## Рабочие адреса

Подтверждённые рабочие измерительные адреса ЯЛК:

```text
1–28
32–43
45–70
74–87
```

Итого:

```text
80 адресов
```

Пропуски не считать измерительными каналами.

## Калибровка

Используются:

```text
адрес 97
адрес 99
```

Адрес 98 не заменяет адрес 99.

Пересчёт напряжения:

```text
UяЛК =
    (code - code97)
    * 6.2
    / (code99 - code97)
```

Значение `6.2` является диапазоном пересчёта.

Фактическое напряжение В7 используется как независимый эталон для
сравнения результата ЯЛК.

Нельзя подменять эталон уставкой ИСД.

Нельзя пытаться компенсировать расхождение В7 командой ИСД выше
допустимого диапазона 0...6.20 В.

## ИСД

ИСД:

```text
192.168.0.101
HTTP
```

Аналоговое воздействие ЯЛК задаётся через:

```text
type=5
val=<volts>
work=1
bus=1
```

Основные точки:

```text
0.0 В
3.1 В
6.2 В
```

Команда `val=4095` не является текущей методикой задания точки ЯЛК.

## Живое подтверждение

02.09.2026 был выполнен диагностический полный проход:

```text
80 / 80 каналов
240 / 240 аналоговых точек
failed_channels = 0
failed_points = 0
```

Этот факт подтверждает физический тракт:

```text
ИСД
  ↓
ЯЛК
  ↓
adapter / UDP
```

и независимое измерение В7.

Это доказательство работоспособности тракта, а не замена нормативному
протоколу испытаний.

# 5. Подтверждённый тракт ЯТП

Команда переключения и запуска ЯТП:

```text
ROKT 0A 02 00 01 00
```

После неё ожидается свежий кадр:

```text
длина: 68 байт
header: 01 00 34 00
структура:
    4-byte header
    +
    32 x uint16 little-endian
```

Слова:

```text
1..30   измерительные каналы
31      верхняя калибровочная точка
32      нижняя калибровочная точка
```

Типичные подтверждённые значения калибровки:

```text
word31 ≈ 4000
word32 ≈ 330
```

Значение:

```text
0x8000
```

означает отсутствие измерения и не является сопротивлением.

## ИСД

Для физического тракта ЯТП подтверждена коммутация `type=7`:

```text
3
9
12
17
```

Коммутация ИСД и запуск ROKT — две разные операции.

## Р4831

Р4831 — ручной магазин сопротивлений.

Компьютер им не управляет.

Текущая проверка использует общие точки:

```text
0 Ом
120 Ом
240 Ом
```

для всех 30 каналов.

На живом стенде при установленном 120 Ом получены значения примерно:

```text
120.26 ... 120.39 Ом
```

# 6. Питание УБСИ

На текущем стенде питание УБСИ контролируется АКИП-1160/6.

Для нормативной проверки используются рабочие точки:

```text
24 В
27 В
35 В
```

и воздействия:

```text
19 В
37 В
```

Общий ток всего УБСИ:

```text
Iобщ <= 0.4 А
```

Это именно измеренный общий ток изделия.

Защитное ограничение источника:

```text
0.6 А
```

не является критерием годности УБСИ.

На стенде подтверждено, что OVP источника может ограничивать напряжение
значением около 31 В.

Для текущей конфигурации используется:

```text
VOLT:LIM 40 В
```

с обратной проверкой.

OVP не отключать.

После холодного включения питания и после воздействий, способных
перезапустить адаптер, необходимо заново выполнить явный запуск ROKT и
дождаться свежего кадра.

Старый `alive` без повторной инициализации не считается доказательством
готовности тракта.

# 7. Текущие решения по покрытию ТУ

Эти решения относятся к текущей программной реализации и не означают,
что текст исходного ТУ уже официально изменён.

## Поканальный ток датчиков

Текущий стенд не имеет достоверного измерительного тракта поканального
тока.

Поэтому запрещено:

- вычислять его из ЯЛК;
- подменять его общим током АКИП;
- выполнять выдуманные автоматические 350/450 мА проверки.

## 1.1.4.4

В текущем автоматизированном TU-run:

```text
НЕ ПРОВЕРЯЕТСЯ
```

Не создавать для него:

- автоматический шаг;
- external evidence;
- ручной acceptance gate.

## 1.1.4.6

Проверка 50-метровой линии:

```text
НЕ ВЫПОЛНЯЕТСЯ
```

Не добавлять её в ЯТП или acceptance-flow.

## Входной ток <= 2 мкА

Текущая аппаратура КТМА не позволяет достоверно измерять такой входной ток
отдельного канала.

Общий ток АКИП и данные ЯЛК не являются его заменой.

Отсутствие этого измерения не превращается автоматически в
`НЕ НОРМА` изделия.

# 8. Перегрузка ЯЛК ±12 В

Текущая методика проверки устойчивости остальных каналов:

```text
физические каналы: 1..88
```

Перед перегрузкой в текущем run должен быть получен baseline.

Для каждого перегружаемого канала проверяются остальные каналы:

```text
delta =
    current_code
    -
    baseline_code
```

Критерий:

```text
abs(delta) <= 2 кодовых единиц
```

Это критерий в кодовых единицах, не `0.5 % FS`.

Между каждым воздействием обязателен safe transition:

```text
снять ±12 В
RESET ИСД
DAC OFF
WAIT
```

Не подтверждены окончательно:

- точная исходная baseline-лесенка;
- точная длительность WAIT.

Их нельзя угадывать.

После исправления чтения старых UDP-кадров требуется новый полный живой
прогон актуальной реализации перегрузки.

# 9. ЯВП-8

Текущий объект:

```text
ЯВП-8 = 8 измерительных каналов
```

Результат ЯВП должен читаться через:

```text
ЯВП
  ↓
ЯЛК
  ↓
UDP adapter
```

`orbita.parameter_source / E20` не является целевым источником результата
УБСИ ЯВП.

Подтверждён допустимый диапазон адресов:

```text
88..96
```

Но диапазон содержит 9 целых адресов, а каналов ЯВП только 8.

Поэтому точную восьмиканальную карту нельзя выводить арифметически.

До commissioning должны быть подтверждены восемь уникальных фактических
адресов внутри диапазона `88..96`.

До подтверждения:

- не считать `89..96` доказанной картой;
- не включать активный генератор;
- не выполнять опасное воздействие;
- процедура должна завершаться `INCOMPLETE` до включения Rigol.

Также требуют commissioning:

- физическая карта ИСД ЯВП;
- получение `Uout` из живых слов;
- окончательная опорная частота;
- окончательный числовой критерий высокочастотного затухания.

# 10. Результат испытания

Строго различать:

```text
НЕ НОРМА
=
достоверное измерение выполнено,
изделие не выполнило требование
```

и:

```text
ОШИБКА
=
стенд / прибор / транспорт
не позволил выполнить достоверное измерение
```

`НЕПОЛНАЯ` используется, когда текущая конфигурация или commissioning
сознательно не позволяют закончить проверку.

Ошибка стенда не должна становиться дефектом изделия.

# 11. Безопасность

1. Один процесс одновременно владеет адаптером и ИСД.
2. Не запускать одновременно production-приложение и референсную KPA.
3. Не fuzz-ить ROKT.
4. Не угадывать неизвестные opcodes и физические маршруты.
5. Не автоматизировать Р4831.
6. После переключения режима требовать свежий кадр ожидаемого формата.
7. Stop, timeout и exception должны приводить оборудование в safe state.
8. После испытания питание должно быть безопасно отключено.
9. Опасное воздействие с неподтверждённой коммутацией не выполнять.
